- Wi-Fi + 可切换的弱网/断网手段（飞行模式或限速工具）。

**前置依赖**：无。

### 2.2 交付物

可安装的 debug APK；能配置接口并完成纯文字对话；数据落库。

### 2.3 验收标准（逐条当场判定）

1. 真机安装后首次启动不白屏，5 秒内出现首页。
2. 不填任何配置直接开始对话 → 出现"先去配置接口"的可点击提示，不崩溃。
3. 填入真实 `base_url`/`key`/`model`，点"测试连接" → 3 秒内显示"可用"。
4. 把 `base_url` 改成错误地址再测试 → 显示可读原因（不是 `DioException` 原文），且保存按钮仍可用。
5. 连续完成 **5 轮文字对话**，每轮 AI 有回复，页面无卡死。
6. 杀进程重开 → 5 轮消息仍在，顺序正确，配置仍在。
7. Key 在设置页只显示尾 4 位；用日志检索 `sk-` 与 `authorization` 命中数为 0。
8. 断网后发一条 → 15 秒内出现"网络/服务异常 + 重试"，不出现无限转圈。

### 2.4 用户能看到 / 怎么验收

- 能看到：首页、设置页、一个只能打字的对话页。
- 验收方式：用户自己在真机上按 2.3 走一遍，约 5 分钟；第 5–8 条由开发者现场演示。

### 2.5 风险点

| 风险 | 影响 | 缓解 |
|---|---|---|
| Drift 迁移/种子写错 | 后续所有数据功能返工 | T0.3 单独验收：删库重装两次，数据一致 |
| 兼容接口不流式或返回异常结构 | M1 延迟与稳定性受阻 | M0 就用非流式跑通，M1 再试流式 |
| 主题 Token 与规范偏差 | M4 视觉返工 | T0.1 完成即对照规范 §3.1–3.5 走查一次 |

## 3. M1 真机跑通一次完整语音对话（关键里程碑）

**目标**：按住说话 → 识别 → 模型回复 → 听到声音，连续 8 回合。

**前置依赖**：M0 全部完成（尤其是 T0.5、T0.7）。

### 3.1 任务

| # | 任务 | 模块 | 交付物 | 工作量 | 并行性 |
|---|---|---|---|---|---|
| T1.1 | 音频会话管理 | `AudioSessionManager` | 进页配置、离页释放、焦点事件回调 | 2 | 与 T1.2 并行 |
| T1.2 | 按住录音 | `AudioRecorder` | 权限申请、16k/单声道/PCM16、30s 上限、<0.4s 取消 | 2 | 与 T1.1 并行 |
| T1.3 | 系统语音识别 | `SystemAsrEngine` | final 结果、空结果、8s 超时、不可用检测 | 2 | 依赖 T1.2 |
| T1.4 | 回合状态机 | `ConversationController` | Idle/Recording/Transcribing/Thinking/Speaking/Error 六态 | 3 | 依赖 T1.3 |
| T1.5 | 流式请求与首句切分 | `OpenAiCompatibleClient.stream`、`SseParser` | SSE 解析、6s 首字超时转非流式、句末切分 | 3 | 与 T1.6 并行 |
| T1.6 | Edge TTS 最小实现 | `EdgeTtsEngine` | WSS 握手、SSML、整段合成、错误抛出 | 5 | 与 T1.5 并行 |
| T1.7 | 播放与重听 | `AudioPlayer` | 播放/停止/重听，播放完成回调 | 2 | 依赖 T1.6 |
| T1.8 | 对话页接线 | `features/conversation` widgets | 麦克风、波形、AI 气泡播放按钮、文字切换 | 3 | 依赖 T1.4、T1.7 |

### 3.2 交付物

可用的语音对话（单场景：咖啡店点单），无提示、无翻译、无复盘。

### 3.3 验收标准

1. 真机上从首页点场景卡 → 点"开始对话" → 听到 AI 开场白，全程 ≤2 次点击。
2. 不重启 App，**连续完成 8 个回合**，每回合都有用户转写和 AI 回复。
3. 静音/杂音环境下说一句 → 8 秒内给出"没听清"或转写结果，不出现永久转圈。
4. 测量"松手 → 听到 AI 首字"时间的 p50 **≤3s**（M1 只要求可用）。
5. 反手把 Edge TTS 域名改成不可用地址 → 本句改用系统 TTS 读出，会话继续。
6. 录音过程中锁屏再解锁 → App 不崩溃；会话不丢失（回到中断前的消息）。
7. 播放中拔掉耳机 → 播放暂停并提示，不出现"外放突然变大"。
8. 拒掉麦克风权限后进入对话 → 自动可用文字输入继续，不需要重开会话。

### 3.4 用户能看到 / 怎么验收

- 能看到：一个真的能"说话练"的 App，AI 会开口回应。
- 验收方式：用户自己完成一次 8 回合对话（约 10 分钟）；第 4 条由开发者现场用秒表/日志测 3 次取中位数；第 5、7、8 条现场演示。

### 3.5 风险点（**本里程碑最可能拖期**）

| 风险 | 说明 | 缓解 |
|---|---|---|
| Edge TTS 握手失败 | 非官方接口，`Sec-MS-GEC` 签名/端点可能已变 | T1.6 之前先写 30 行脚本验证连通；失败则整场先用系统 TTS，不阻塞其余任务 |
| 国产 ROM 无系统识别 | 部分机型没有 Google 语音服务 | 先检测可用性；不可用即降级文字 + 把 Whisper 提前到 M2 首项 |
| 录音与识别争麦克风 | 系统识别内部也占用麦克风 | 采用"识别引擎独占录音"模式，不自采 PCM 双开 |
| 音频焦点混乱 | 播放/录音切换导致无声 | T1.1 统一管理，任何播放前先确认焦点 |

## 4. M2 语音链路稳定与降级

**目标**：把"能跑"变成"不容易坏"，延迟达标，失败有出路。

**前置依赖**：M1 完成。可与 M3 并行。

### 4.1 任务

| # | 任务 | 模块 | 交付物 | 工作量 | 并行性 |
|---|---|---|---|---|---|
| T2.1 | 统一超时/重试/取消 | `OpenAiCompatibleClient`、`ConversationController` | 各环节超时表、退避重试、`CancelToken` | 3 | 与 T2.2 并行 |
| T2.2 | 朗读路由与熔断 | `TtsRouter`、`SystemTtsEngine` | 失败切系统 TTS、连续 2 次熔断、恢复策略 | 3 | 与 T2.1 并行 |
| T2.3 | 语音缓存 | `TtsCache` | 键生成、命中、LRU 80MB、清理入口 | 2 | 依赖 T2.2 |
| T2.4 | 播放队列与变速 | `AudioPlayer`、`ConversationController` | 逐句入队、0.75–1.2x、队列取消 | 2 | 依赖 T2.2 |
| T2.5 | 设备切换与中断 | `AudioSessionManager` | 耳机/蓝牙切换、来电暂停、恢复不自动续播 | 3 | 与 T2.1 并行 |
| T2.6 | 弱网与错误态 UI | `features/conversation` | 顶部提示条、四类错误文案、重试按钮 | 2 | 依赖 T2.1 |
| T2.7 | 端侧识别（可选） | `WhisperAsrEngine` | 模型加载、文件识别、开关 | 5 | 可与 T2.5 并行 |
| T2.8 | 延迟埋点 | `ConversationController`、`message.latency_ms` | 松手→首音、请求→首字 | 1 | 与 T2.1 并行 |

### 4.2 交付物

稳定的语音链路 + 降级能力 + 可观测的延迟数据。

### 4.3 验收标准

1. 本地 Wi-Fi 下测 10 次"松手 → 首音"：p50 **≤1.5s**，p95 **≤3s**。
2. 连续 20 回合，无一次"以为在播其实没播 / 播了但按钮还在转"的状态错乱。
3. 限速到 100 kbps 后发起一回合：**15 秒内**出现可操作提示（重试/改文字），不出现超过 30 秒的无反馈等待。
4. 断网状态点重听：命中缓存则立即播放；未命中则提示"网络不可用"，不崩溃。
5. 手动禁用 Edge TTS：整场 8 回合全部用系统语音完成，只提示一次。
6. 播放中接听来电 → 播放暂停；挂断后不自动续播，出现"继续播放"。
7. 同一句连点重听 3 次：第 2、3 次无可感知延迟（缓存命中，日志显示 `fromCache=true`）。
8. 蓝牙耳机连接状态下完成一回合：录音有输入、播放从耳机出声。

### 4.4 用户能看到 / 怎么验收

- 能看到：AI 回应明显更快，断网/朗读失败时不再卡死。
- 验收方式：开发者现场跑 10 次延迟测量并出示日志；用户用蓝牙耳机完成一次 5 分钟对话；第 3 条用限速工具现场演示。

### 4.5 风险点

| 风险 | 影响 | 缓解 |
|---|---|---|
| 延迟压不下去 | 对话感差，用户放弃 | 首句切分 + 缓存 + 限制 AI 回复长度；优先保证 p50 |
| 蓝牙切换机型差异 | 个别机型录不到音 | 只保证"不崩溃 + 有提示"；兼容性矩阵记录在案 |
| Whisper 包体/性能 | 安装包过大、发热 | 默认关闭，按需下载模型 |

## 5. M3 复盘、记录、表达本

**目标**：练完能看见收获，历史能回看。

**前置依赖**：M0 + M1（需要 `message` 有真实数据）。可与 M2 并行。

### 5.1 任务

| # | 任务 | 模块 | 交付物 | 工作量 | 并行性 |
|---|---|---|---|---|---|
| T3.1 | 复盘生成 | `ReviewService`、`PromptBuilder` | 结构化输出 + 容错解析 + 失败重试 | 3 | 与 T3.4 并行 |
| T3.2 | 复盘页 | `features/review` | 亮点卡、改法列表、表达列表、下次建议、底部按钮 | 3 | 依赖 T3.1 |
| T3.3 | 纠错标记与展开 | `AiBubble`、`UserBubble`、`correction` 表 | 小标记、展开详情、试听、删除 | 2 | 依赖 T3.1 |
| T3.4 | 记录列表与详情 | `features/history` | 列表、只读转写、纠错展开 | 2 | 与 T3.1 并行 |
| T3.5 | 表达本 | `features/phrasebook` | 列表、试听、删除、来源 | 2 | 与 T3.4 并行 |
| T3.6 | 首页统计与"上次卡在哪" | `features/home`、`session` 聚合 | 本周次数/分钟/连续天数、卡点卡 | 2 | 依赖 T3.4 |
| T3.7 | 删除与清空 | `SessionRepository`、`TtsCache` | 删会话级联、清空数据、清缓存 | 1 | 依赖 T3.5 |

### 5.2 交付物

复盘页 + 记录 + 表达本 + 首页统计 + 数据清理。

### 5.3 验收标准

1. 结束一次 8 回合会话后，**30 秒内**出现复盘页，包含：1 个亮点、≤3 条改法、2 个表达、1 条下次建议。
2. 每条改法都能播放音频；点"存表达"后，表达本列表在 1 秒内出现该条。
3. 让模型返回非结构化内容（用错 prompt 模拟）→ 页面显示"本次未能生成总结 + 重试"，**不出现乱码或崩溃**。
4. 删除一条改法 → 该条消失，会话记录其余内容不受影响。
5. 杀进程重开 → 记录列表、表达本、首页统计数字与关闭前一致。
6. 删除一次会话 → 列表少一条；其音频文件在缓存目录中不存在。
7. 清空所有数据 → 记录/表达本/Key 全部清空，回到首次启动状态。
8. 连续两天各完成一次会话 → "连续天数"显示 2；跳过一天后显示 1。

### 5.4 用户能看到 / 怎么验收

- 能看到：完整的"练习 → 复盘 → 保存 → 回看"闭环。
- 验收方式：用户完整走一遍 10 分钟练习并保存 2 个表达；开发者演示第 3、6、7 条。

### 5.5 风险点

| 风险 | 影响 | 缓解 |
|---|---|---|
| 模型输出格式不稳定 | 复盘页空白/错乱 | 容错解析 + 一次重试 + 明确失败态；不硬解析 JSON |
| 复盘提示词太长导致超时 | 30 秒内出不来 | 用压缩后的会话摘要，不带全量转写 |
| 统计口径不一致 | 数字对不上，失去信任 | 统计只从 `session` 聚合，不另存冗余计数 |

## 6. M4 第二场景 + 提示/翻译 + 打磨

**目标**：功能补齐到 MVP 验收清单，能长期用。

**前置依赖**：M1、M2、M3。

### 6.1 任务

| # | 任务 | 模块 | 交付物 | 工作量 | 并行性 |
|---|---|---|---|---|---|
| T4.1 | 第二个场景内容 | `scenario` 种子 | 工作会议澄清：角色/目标/开场白/5 表达/分支 | 2 | 与 T4.5 并行 |
| T4.2 | L1–L4 提示 | `RequestHint`、`HintRail`、`HintSheet` | 重听/关键词/参考回答/中→英 | 3 | 依赖 M1 |
| T4.3 | 翻译三态与"我想说" | `TranslateMessage`、`ComposerBar` | 关闭/点按/常开、中→英建议（不自动发送） | 3 | 与 T4.2 并行 |
| T4.4 | 空态与异常态补齐 | 各 `features/*` | 首页/记录/表达本/对话/复盘的空态与错误态 | 2 | 与 T4.1 并行 |
| T4.5 | 成本估算与上限提示 | `ConversationController`、设置页 | 单次估算、月度累计、超限提示 | 2 | 与 T4.1 并行 |
| T4.6 | 视觉走查 | `app/theme`、各页面 | 对照 UI 规范 Do/Don't 修正 | 2 | 依赖 T4.4 |
| T4.7 | 全量回归 | 全部 | 需求 §10.2 验收清单逐条跑通 | 2 | 最后执行 |

### 6.2 交付物

MVP 完整功能 + 一份逐条通过的验收记录。

### 6.3 验收标准

1. 两个场景各完整跑 **3 次**，每次 ≥8 回合，无阻塞性问题。
2. L1–L4 四级提示都能触发；任何一级都**不会自动发送**回答（点完提示后 AI 不会自问自答）。
3. 翻译关闭时，对话页中文出现次数为 **0**（设置/帮助除外）；点按后 2 秒内出中文。
4. "我想说"给出 1 句英文，且不会自动发出；用户必须再按一次麦克风或发送。
5. 首页/记录/表达本三处空态都有引导文案，不是空白页。
6. 需求文档 §10.2 的 **11 条 MVP 验收清单全部勾选通过**，无"部分通过"。
7. 所有失败路径（断网、401、429、TTS 失败、识别为空）都能在 **15 秒内**给用户一个明确下一步。

### 14.1 用户反馈与任务

### 14.2 验收标准（本次新增，不替代需求 §10.2）

1. 说完或发出一句后即时出现一次动效；等待回复、计时器刷新均不重复触发，动效不拦截任何点击。
2. 三枚图标都可用：优化结果页内展开且可试听 / 存入表达本，原声可回放（无录音有明确提示），朗读能读出该句；三者都不改写已发送消息、不自动发送。
3. 自建场景可新建、编辑、删除并直接开练；场景库里带「自建」标识，内置场景无编辑 / 删除入口；删除不影响历史会话。
4. 点提示项不出现弹窗，参考答案在页内展开；结果不自动发送、不进对话历史。
5. 首次安装打开表达本即有内容与常驻添加入口，可增删改与朗读；用户删改过的初始表达不会被重新灌回。
6. 上滑浏览历史时不会被拉回底部（触摸 / 滚轮 / 触控板 / 惯性均适用）；回到底部后恢复自动跟随，「回到最新」浮标可用。
7. `flutter analyze` 无 error / warning，`flutter build web --release` 通过。
