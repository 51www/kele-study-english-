## 1. 隔离原则（本轮硬约束）

1. **不改验收口径**：需求 §10.2 的 11 条 MVP 清单保持未勾选；二期 M5–M8 的验收标准与「老数据零丢失」口径不变。
2. **不动主链路**：不改底部 4 Tab、不改 `ConversationController` 主对话状态机、不改 `HintRail` / 复盘生成主流程的失败重试语义；新入口挂首页栏目或现有页面内。（M12 例外：Q2 已拍板解锁，只注入 `chatSystem`）
3. **不动旁路语境约束**：需求 §0.3 第 7 条规定「优化句子 / 提示」的 `SessionContext` 严格限于本次会话消息 + 场景卡，本轮一律不改；M12 已解锁，但**只改主对话 `chatSystem`**，不扩旁路快照范围（见需求 §0.3 第 8 条）。
4. **老数据零丢失**：SQLite 从 v2 升 v3，`onUpgrade` **只 `createTable(reviewItems)`**，不 `ALTER` / `DROP` / 回填老表；覆盖安装不清数据仍能续练、记录、表达本、教材与错句本都在。
5. **复盘扩展零迁移**：新增字段一律走已有的 `session.review_json`（`ReviewResult.toJson/fromJson`），`correction` 表保持原三列；旧版本 `review_json` 必须能正常解码。
6. **复习与判分离线**：复习排程是纯 Dart 规则；「说对没」复用 `DictationScorer.score` 纯函数。**两者都不调用 `/chat/completions`**；ASR 失败或无麦克风权限时降级为键盘输入。
7. **不引入分数**：不做发音分数、不做 CEFR 等级、不做排行榜 / 勋章 / 连胜打卡；能力轨迹只给可解释趋势。
8. **延续非目标**：不做账号 / 支付 / 订阅 / 云同步 / 多语言 / 课程大纲 / 场景市场 / 平台下载；不做虚拟人、全双工打断、边聊边纠错、严格纠错模式。
9. **两端实现同补齐**：`LocalStore` 新增方法必须同时补 `drift_store.dart` 与 `web_store.dart`，并接入 `clearAll`；否则 Web 端编译失败（二期 T5.2 同一风险）。
10. **文档与代码同批**：新增 UI 组件先改 UI 设计规范再改代码；截图按 `docs/shortscreen/milestone-9/`–`milestone-12/` 分子目录、文件名带序号（沿用本轮用户指令与 M9 既有目录）。
11. **提示词扩展可空**：新增输出字段一律可选 + 宽容解析；模型不按格式返回时，原「亮点 / 改法 / 表达 / 下次建议」必须完整可用，不显示半成品。

### 4.2 交付物

复盘页底部可完成一次 90 秒开口复述；表达本、错句本、复盘改法统一进入一个到期队列；首页一张卡直接给出今天该练什么。原有会话、教材、密钥、设置完全不受影响。

### 4.3 验收标准（逐条当场判定）

1. 结束并复盘后，页面内可在 90 秒完成一次「看改进句 → 说一遍 → 看到已过 / 再来」，全程不新增 `/chat/completions` 请求。
2. 断网、无模型密钥时，90 秒练习与到期筛选仍可用；ASR 失败 / 无权限时一键切键盘，输入内容不丢。
3. 隔天打开 App 有待复练项；答对后到期日顺延到下一档，答错后间隔缩短；连续答对到顶后该项标记为已巩固且不再天天出现。
4. 首页「今天练这个」能一键开始，卡上的理由与数据对得上（如「上次用了 4 次提示」）；无任何历史数据时给可用入口而非空白。
5. 表达本标记、错句本条目都能进队列且不产生重复复习项；删除表达 / 删除教材后，对应复习项也查不到。
6. 覆盖安装 v2→v3（不清数据）后，原有会话、表达本、教材库、错句本、密钥、设置全部仍在；旧 `review_json` 能正常打开只读复盘，不出现乱码或崩溃。
7. 模型未按扩展格式输出时，原「亮点 / 改法 / 表达 / 下次建议」完整显示，不出现空卡或半截内容。
8. `flutter analyze` 0 error / 0 warning；`flutter test` 全通过；Web release 与 Android debug 构建通过。

### 4.4 风险点

| 风险 | 缓解 |
|---|---|
| 复盘页接入 ASR 与全局 TTS 播放器抢音频焦点 | 进入练习前调用既有 `stop()`；练习用与听写同款的独立实例，页面 `dispose` 释放；不改 `AudioPlayerService` 契约 |
| `DictationScorer` 的听写口径（缩写/数字等价、90% 线）不适合口语复述 | 独立 `review.speakPassThreshold`，默认 0.8；复用规范化但不复用听写设置；规则在界面可见 |
| 复习队列膨胀成「每天 30 条」 | 每次复盘最多入队 1 条重点 + 用户显式收藏项；每日待复练上限可配置，超出顺延不顺手堆 |
| `LocalStore` 双端漏改导致编译失败 / Web 端数据丢失 | 抽象先落地，`drift_store` 与 `web_store` 同一次改动补齐；`clearAll` 与级联删除一并接上 |
| 升级后旧复盘 JSON 缺新字段 | `fromJson` 全部可空 + 默认值；单测固定一份旧版样例 |

| T10.2 | 场景目标清单 | `data/db/seeds.dart`、`features/scenario` | 26 个内置 `success_criteria` 改写为 3 条编号目标；纯解析函数；对话页顶部可折叠目标条（自建场景退化为 1 条） | 3 |

| T10.6 | 单测与 UI 规范同步 | `test/`、`docs/UI 设计规范.md` | 解析容错、生成失败回退、热身跳过与 TTS 降级；新增卡片 / 目标条 / 展开区组件规格 | 2 |

### 5.2 交付物

复盘改法能说明「为什么中国学习者会这么说」并给出两种语体的说法；每个场景开场前就知道要办成哪 3 件小事、结束能看到达成情况；自建场景一句话即可起稿；低水平用户进对话前有 60 秒缓冲。

### 5.3 验收标准

1. 同一句用户输入放在「咖啡店点单」与「会议澄清」下，日常版 / 正式版明显不同且各带一句适用场合说明。
2. 模型只返回原有格式时，复盘页无空卡、无报错，三列内容完整；解析异常不会让「结束并复盘」流程失败。
3. 26 个内置场景详情页与对话页都能看到 3 条编号目标；自建场景不因解析失败而空白或崩溃。
4. 复盘显示 3 条达成结果；判定失败或模型异常时不影响复盘本身生成；「只练这条」能开新会话并带上场景。
5. 输入一句中文描述即可生成可保存、可开练的场景卡；生成失败 / 超时可一键回退手填，不落半成品场景、不新增模型配置。
6. 课前热身全程 ≤60 秒、默认关闭、随时可跳过；跳过不影响直接开练；TTS 不可用时降级为纯文字且能继续。
7. 跟读只判断「关键词是否说出」，界面**不出现任何分数 / 等级 / 星级**。
8. 覆盖安装后 26 个场景的新目标清单生效，用户自建场景与历史会话不被覆盖或丢失。

### 5.4 风险点

| 风险 | 缓解 |
|---|---|
| 提示词加字段后结构化输出更不稳 | 新增字段全部可选；保留现有 `degraded` 判定与自动重试一次；失败按旧格式渲染 |
| 种子 upsert 覆盖用户改过的场景内容 | 只对 `is_builtin=1` 且 id 在 26 个清单内的记录更新目标字段；自建场景不进 upsert 范围（沿用既有幂等策略） |
| 「通关判定」被理解成分数 | 文案与 UI 只用「已达成 / 待练」，不给百分比、不做评级；见第 1 节第 7 条 |
| 一句话生成场景消耗过多 token / 生成质量不稳 | 复用旁路 `maxTokens` 档位与超时表；结果必须经结构化校验才允许保存；不提供「直接开练」 bypass |
| 课前热身变成强制预习、拖慢「2 次点击开练」 | 默认关闭、可跳过、不阻塞主按钮；验收按「跳过不影响开练」判定 |

## 6. M11 让进步可解释

**目标**：低能量日有 3 分钟入口；能明确回答「哪方面变好了、凭什么」，且不引入任何分数。

### 6.1 任务

| # | 任务 | 模块 | 交付物 | 点数 |
|---|---|---|---|---|
| T11.1 | 3 分钟轻量模式 | `features/home`、`features/chat` | 首页入口 = 1 条待复练 + 3 回合微对话 + 1 条重点；复用 `session` 表，用 `targetMinutes=3` 区分粒度 | 3 |
| T11.2 | 趋势指标纯逻辑 | `features/me/metrics.dart` | 先落 2 条：提示使用率、改法复现率；近 4 周分桶、口径可解释；另 2 条按同一接口预留 | 3 |
| T11.3 | 「我的」趋势区 | `features/me/me_page.dart` | 近 4 周折线 + 每项「怎么算的」说明 + 空态；纯本地聚合、无网络请求 | 2 |
| T11.4 | 全量回归与文档同步 | 全部 | `flutter analyze` / `flutter test` / Web release / Android debug；UI 规范、开发文档、需求 §11 回写（Q1–Q4 拍板后） | 2 |

### 6.2 交付物

3 分钟轻量练习与 2 条可解释趋势线；趋势每项都能点开看计算口径，无分数、无等级、无排名。

### 6.3 验收标准

1. 3 分钟模式从首页 ≤2 次点击开始，含 1 条待复练、3 回合内可结束、产出 1 条重点；会话正常落库、可回看。
2. 3 分钟会话**不计入** §3.2「每周 ≥3 次、每次 ≥8 分钟」的有效次数，但计入今日分钟；该口径在界面可见，不与首页周计数冲突。
3. 趋势数据全部来自本地已有表，断网 / 无密钥可用；每项点开能看到「怎么算的」的人话说明。
4. 界面不出现总分、CEFR 等级、雷达图、热力图、排行榜、勋章、连胜天数以外的游戏化元素。
5. 连续 4 周数据能画出折线；只有 1 次练习时给明确空态而不是假趋势或 0 分。
6. `flutter analyze` 0 error / 0 warning；`flutter test` 全通过；Web release 与 Android debug 构建通过；对照需求 §10.2 的 11 条 MVP 清单与二期 M5–M8 验收逐条回归无失败。

### 6.4 风险点

| 风险 | 缓解 |
|---|---|
| 「改法复现率」口径难以自证 | 定义写进界面：上次改法中的关键表达在后续会话被再次正确使用即记一次；只统计可匹配到的，样本不足时不显示比率 |
| 3 分钟模式与 10 分钟模式统计口径打架 | 单一 `session` 表 + `targetMinutes` 区分；有效次数的过滤条件集中在同一 Provider，避免「两套进度」 |
| 趋势图诱导刷数据 | 不做分数、不给目标线、不发勋章；只呈现事实趋势与解释 |

### 7.2 验收标准

1. 同一场景连续 3 次练习不出现重复开场白与同类提问；AI 仍每次 ≤2 句、只问 1 个问题。
