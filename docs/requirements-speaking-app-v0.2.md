### 0.2 会话续练（2026-11-10 用户反馈）

> 用户反馈：「**之前练到一半的对话，半路退出后没办法重新继续进行对话**」。这是 F2 / F6 的能力缺口，按用户反馈补齐，不改 MVP 验收口径。

**根因**：半路退出直接调用 `endSession()` 把会话标成 `completed` 并写 `ended_at`，弹窗却写着「保存为草稿」；练习记录里所有卡片一律跳 `/review/:id`（只读复盘），首页「继续上次」也只对未完成状态才进 `/chat/:id`，于是没有任何续练入口。

**规则**：

| 项 | 定义 |
|---|---|
| `draft` | 已创建、还没说过话（只有 AI 开场白）；退出可删除该空会话 |
| `in_progress` | 至少说过 1 轮、用户**没有**显式点「结束并复盘」；可多次退出 / 续练 |
| `completed` | 只有「结束并复盘」才会写入；生成复盘，记录页进只读复盘 |
| 半路退出 | 保留全部消息、回合数、累计时长与成本，状态回 `in_progress`，清空 `ended_at`；不生成复盘 |
| 续练入口 | 首页「继续上次」卡、练习记录「进行中」卡、场景详情「继续上次」按钮，三处都进 `/chat/:id` |
| 时长 | 用会话内累计秒数（每 15 秒 + 退出时落盘），不用 `现在 - started_at` 的墙钟差，避免多段续练把时长算成几小时 |
| 断句恢复 | 若最后一条是用户消息（上次没等到 AI 回复），只提示「重试」，由用户显式触发，不自动补发 |
| 旧数据 | 升级时一次性回收「曾被误标 completed 且无复盘」的会话，并重算未完成会话里明显虚高的时长；各带 `app_meta` 标记只跑一次，不动已完成复盘 |

**验收标准（新增，不替代 §10.2）**

1. 说到一半点返回 / 系统侧滑返回 / 杀进程，重新打开 App 仍能看到这次未完成对话，且能从上述三处入口接着往下说。
2. 续练后消息、轮次、成本、翻译缓存与计时连续，不重放开场白、不新建会话。
3. 「结束并复盘」仍然生成复盘并标为已完成；已完成记录点进去仍是只读复盘。
4. 旧版本误标为 `completed` 且没有复盘的会话，升级后一次性回收为可续练，且只跑一次。

§10.2 的 11 条 MVP 验收清单**保持未勾选**；本条不涉及语音链路、提示阶梯与翻译三态的改动。

### 0.3 对话交互体验优化（2026-11-11 用户反馈）

> 用户要求「完成回答后有正向反馈、回答句下方可优化 / 听原声 / 听朗读、支持自定义场景、提示就地展开」，同时反馈「表达句板块既无内容也无添加入口」「对话页上滑看历史会被强制拉回底部」。以下为**用户决策**，本节优先于下文中与之冲突的历史表述；§10.2 的 11 条 MVP 验收清单仍保持未勾选。

| # | 变更 | 口径 |
|---|---|---|
| 1 | 正向反馈 | 每完成一次回答，对话区即时播放一次轻量粒子 / 烟花动效与鼓励语；只由「新增用户消息」触发，不被计时器等周期性刷新反复触发；不拦截点击、不打断对话 |
| 2 | 回答句操作栏 | 每条用户回答下方右对齐三枚纯图标入口：优化句子 / 播放我的原声 / TTS 朗读该句；无录音时原声置灰并说明原因；优化结果页内展开，可试听或存入表达本，不改写原句、不自动发送 |
| 3 | 自定义场景 | F9 由 P1 提前启用：支持创建、编辑、删除个性化场景（场景名、中英文标题、分类、难度、AI 角色、练习目标、目标表达、开场白、完成标准、轮数），保存后与内置场景一样可直接开练；仅自建场景可编辑 / 删除，内置场景只读；删除不影响历史会话 |
| 4 | 提示交互 | 点「提示」直接展开 L3 参考回答：不再展示 L1–L4 提示项，也不用底部弹层；结果卡只显示英文 + 一行中文对照（不带「译」前缀），只放内存，不自动发送、不写入对话历史 |
| 5 | 表达句板块 | 首次进入即有可朗读、可编辑、可删除的初始表达，顶部常驻「添加表达」表单，空态提供一键添加与常用表达推荐；用户删除或编辑过的初始表达不被重新灌回 |
| 6 | 对话页滚动 | 仅当「对话内容真的变了」且用户处于底部时才自动滚到最新；用户主动上滑（触摸 / 滚轮 / 触控板 / 惯性）即停止跟随，可自由浏览完整历史，回到底部或点「回到最新」后恢复 |
| 7 | 优化与提示结合语境（2026-11-12） | 「优化句子」与「提示」的答案要结合**当前对话的内容与场景设置**：沿用上文话题、角色与已出现的细节，不退化成脱离场景的通用改写或万能兜底句；语境范围严格限于本次会话消息 + 场景卡，不含用户水平、纠错/复盘与其它会话。输出格式、结果卡、不改写原句、不自动发送、不写入对话历史的口径均不变 |
| 8 | 主对话防脚本化（2026-11-12 用户拍板 Q2） | 允许**主对话 `chatSystem`** 注入一份只读、有长度上限的「学习者档案」：最近常犯的 1–2 类错误、3 条已掌握表达、上次话题，用于避免重复提问并主动深挖一层；可在设置里一键关闭。**第 7 条的旁路 `SessionContext` 口径不变**——「优化句子 / 提示」仍严格限于本次会话消息 + 场景卡，不读其它会话、纠错/复盘或表达本。AI 仍每次 ≤2 句、只问 1 个问题；§10.2 的 11 条 MVP 清单保持未勾选 |

**验收标准（本次新增，不替代 §10.2）**

1. 发送或说完一句后立刻出现一次动效反馈；等待 AI 回复、每秒计时刷新都不会重复触发。
2. 三条图标入口均可点：优化给出更自然的说法与中文理由，原声能回放本次录音（无录音时有明确提示），朗读能读出该句；任一操作都不改变已发送的消息。
3. 新建的自定义场景出现在场景库、能开始对话、能编辑与删除；内置场景不出现编辑 / 删除入口。
4. 点「提示」不出现弹窗也不出现提示项列表，参考答案直接在面板内展开；关闭提示后面板与结果一起消失。
5. 首次安装打开表达本即有内容与常驻添加入口，可新增、编辑、朗读、删除。
6. 上滑浏览历史时新消息到达不会被拉回底部；回到底部后新消息恢复自动跟随。
7. 同一句用户输入放在两种不同话题 / 场景的前文下，优化结果与提示参考答案各自贴合当前语境、明显不同；结果仍不改写原句、不自动发送、不写入对话历史。

### 0.4 学习路径（2026-11-13 用户拍板）

> 用户确认「按方案默认口径执行」：`docs/design-learning-path-v0.1.md` 的 Q1–Q6 全部按建议默认采纳，**学习路径正式进入需求范围**。本节优先于下文中「不做系统课程 / 训练计划生成列为范围外」的历史表述；§10.2 的 11 条 MVP 验收清单**仍保持未勾选**。

**定位**：学习路径是现有场景、表达、教材与复练内容之上的一层**轻量阶段导航**，不是课程体系。不生产新内容、不排课表、不解锁、不考试、不推送；底部 4 Tab、场景库自由浏览与「随时开始、随时结束」的偏好保持不变。需求 §3.3「不做系统课程 / 考试备考」与三期里程碑 §8「不做 AI Agent 主动推送训练计划 / 每日提醒」继续有效，本功能不触碰这两条红线。

**拍板口径**

| # | 问题 | 结论 |
|---|---|---|
| Q1 | 是否进入范围 | 进入，按「轻量阶段导航」；标准分级课程仍不做 |
| Q2 | 起点怎么定 | 水平自评 + 最近几次练习的真实表现；**不做入门测评、不打分、不出等级** |
| Q3 | 阶段要不要解锁 | 不解锁，可跳、可退、可换序；完成标准只是「建议往前走」 |
| Q4 | 目标维度 | 工作 / 旅行 / 日常 / 综合 + 每次时长与每周次数；不做考试类目标 |
| Q5 | 完成标准呈现 | 「已达成 / 待练」+ 可核对的次数与证据，不折算分数或百分比 |
| Q6 | 自动调整顺序 | 允许，但每次调整必须给出理由，且用户可手动改回 |

**功能口径**（详见设计文档 §3–§6、F16）

1. 首次 3 问定起点：当前水平、目标场合 + 一句具体诉求、投入节奏；已有练习记录时优先用最近几次的真实表现。
2. 按起点与目标**动态生成四阶段计划**：开口起步 → 稳定表达 → 场景拓展 → 自主运用；每阶段明确学习目标、内容范围、推荐顺序与完成标准，阶段内 5–7 条可直接点开的轻量安排。分类与场景数量按 `builtinScenarios` 实际数据动态取，不写死；场景库扩容后自动纳入。
3. 生成与调整全部用**可见、可解释的本地规则**：每次练习后按 3 条目标达成、提示与翻译依赖、到期复练、上次卡在哪重排下一项；每周回顾与阶段结束再校准；断网、无模型密钥时路径与进度照样可看。不新增模型调用或联网依赖。
4. **进度追踪**：路径页回答「我在哪 / 走到哪了 / 接下来做什么」；阶段安排有状态（未开始 / 已完成 / 待巩固 / 今天跳过）；阶段回顾给「进入下一阶段 / 再巩固一轮 / 换目标重排」三个出口，并附三条可解释证据。与首页周次数、连续天数、3 分钟轻量「不计入主指标」的口径一致；断档不惩罚、不显示负向标记。
5. **下一步行动指引**：首页「今天练这个」升级为「下一步」卡，必带一句可核对的理由、一键开始、以及「换一个 / 今天先跳过 / 查看学习路径」；复盘末尾给「下一次练这个」；场景库加「适合当前阶段」提示但不隐藏其它场景；低能量日走 3 分钟轻量、断档回归给「接着上次 / 从轻量开始」。
6. 复用已有但原先没汇总的能力：每次复盘的 3 条目标自评汇成阶段进度；表达本「已掌握」与复练「已巩固」在路径里可见；统一「设置里的水平」与场景难度标签的口径；设置页补上原先没有界面入口的开口复述阈值与每日待复练上限。
7. **仍然不做**：总分、CEFR 定级、能力雷达、薄弱项热力图、勋章、连胜、排行榜、每日推送、课程大纲、课时解锁、题库、新内容库。

**验收标准（本次新增，不替代 §10.2）**

1. 首次打开能完成 3 问并生成一条四阶段路径；改目标 / 改起点后只重排计划，历史练习、表达本、复练与已巩固内容不丢。
2. 路径页当场能回答「我在哪 / 走到哪了 / 接下来做什么」，阶段安排 5–7 条且每条可点开、有状态、可跳可换序；跳过不锁后续、不补作业。
3. 首页「下一步」卡的理由与用户自己的记录对得上（到期复练数 / 上次提示次数 / 本阶段剩余条数），从打开到开始练习 ≤2 次点击；无历史数据给可用入口而非空白。
4. 每阶段都有可见的目标、范围、顺序与完成标准；达标后给出下一阶段建议但**不阻塞**继续练；不出现分数、等级、百分比、星级、锁图标。
5. 复盘末尾、场景库阶段标记、设置入口、断档回归与低能量日入口均可用；场景库仍可自由浏览全部场景。
6. 清空练习数据后路径回到未配置空态，不残留旧进度；断网、无模型密钥时路径与进度仍可查看。
7. 需求 §3.2 主指标（连续 4 周、每周 ≥3 次、每次 ≥8 分钟）与次指标口径不变；3 分钟轻量仍不计入每周有效次数。
8. `flutter analyze` 0 error / 0 warning；`flutter test` 全通过；Web release 与 Android debug 构建通过。

## 1. 背景与问题

### 1.1 要解决的问题

不是"没有英语学习资料"，而是：

1. **开口门槛高**：不知道怎么开始、怕说错、卡住时没人给台阶。
2. **练完没反馈**：聊完了，但不知道哪句不地道、下次改什么。
3. **难以长期坚持**：课程太重、每次要准备很久；自由聊又容易变成"随便说说"。
4. **听力和口语脱节**：看字幕能懂，关掉字幕就慌；翻译一开，又变成阅读练习。

【依据：调研结论 + 推理】现有产品分别解决了其中一部分，但很少同时做到"低门槛开始 + 可控翻译 + 有台阶的提示 + 轻量复盘"。

### 1.2 现有方案为什么不够

| 现有方案 | 能解决 | 不够的地方 | 依据 |
|---|---|---|---|
| 课程型 App（Speak、ELSA、流利说） | 有路径、有评测、适合打基础 | 课程重、进阶后重复、自由表达少；个人自用容易变成"完成任务" | 调研 S1/S6/S33/S4 |
| 自由对话型（Loora、TalkPal、ChatGPT Voice） | 随时开口、话题自由 | 反馈浅或容易错过；缺少"场景目标"和复习；ChatGPT 倾向夸用户 | 调研 S13/S19/S44 |
| 真人外教（Cambly） | 真实互动、可追问 | 贵、时间不自由、老师质量不稳定 | 调研 S25/S26 |
| 游戏化入口（多邻国） | 习惯强、门槛低 | 口语输出强度低、纠错粗，官方明确 Lily 不纠语法 | 调研 S28/S31 |
| 自己找语伴/自言自语 | 免费、自由 | 没有反馈、没有结构、难以坚持 | 推理 |

### 1.3 机会点

- 个人自用不需要"大课程库、社交、排行榜、支付"，可以把体验压到**一个场景、10 分钟、一次复盘**。
- 主流产品把翻译/提示做成增值功能或藏得很深；个人产品可以做成**默认关闭、随时可开的听力训练开关**。
- 多数产品的反馈"散落在对话里"；个人产品可以把反馈收口成**课后 1 个重点 + 最多 3 条改法**。

【依据：调研结论 1–6 + 推理】

## 3. 产品目标与非目标

### 3.1 目标

1. **让"开始练"这件事足够轻**：打开 → 选场景 → 10 分钟内完成，不需要预习、不需要约时间。
2. **让"卡住"有台阶**：重听/慢速 → 关键词 → 参考回答 → 中→英，不直接给答案。
3. **让"练完"有收获**：每次最多 3 条具体改法 + 2 个可复用表达，下次还能看到。
4. **让"坚持"有记录**：本周练了几次、每次多久、上次卡在哪；不做排行榜。

【依据：调研结论 1–6 + 推理】

### 3.2 成功标准（个人自用）

**主指标**
- 连续 4 周，每周至少 3 次、每次至少 8 分钟的场景对话。

**次指标**
- 每次对话 ≥8 个有效回合（用户开口且 AI 回应）。
- 每次提示使用 ≤3 次；翻译查看 ≤30% 的 AI 消息。
- 每次至少保存 2 个表达到"表达本"。
- 自评"敢开口"分数从 3/5 提升到 4/5（每月自评一次）。

**护栏指标**
- 首段 AI 语音延迟：p50 ≤1.5s，p95 ≤3s（本地网络）。
- 单次会话 API 成本可计量，且不超过设定上限（具体金额待拍板）。
- 无数据丢失；杀进程重启后历史、表达本、设置仍在。
- ASR 识别失败时，用户可以在 10 秒内改用文字继续，不中断会话。
- **朗读不可用时**（Edge TTS 失败），会话仍可只用文字继续，不出现卡死。

【依据：推理；延迟经验值参考调研 S47/S48】

### 3.3 非目标（明确不做）

| 非目标 | 原因 |
|---|---|
| 系统课程/考试备考（雅思、托福、四六级） | 个人自用不需要课程库；课程是重资产，容易变成"完成任务" |
| 真人外教/语伴匹配 | 成本高、时间不自由；AI 已能满足日常练习 |
| 社交/排行榜/学习社区 | 单用户产品，社交价值低；容易增加维护成本 |
| 多语言（先只做英语） | 目标明确，避免场景和提示体系复杂化 |
| 支付/订阅/账号体系 | 个人自用不需要商业化；账单也是行业最大差评源 |
| 云端同步/多端实时同步 | MVP 本地优先；多端是后续问题 |
| 虚拟人/视频通话/全双工打断 | 成本高、延迟高；虚拟人被用户吐槽分散注意力 |
| 发音分数/音素级评分 | 评分准确性争议大，容易引发刷分；先做"可理解度 + 具体改法" |
| 完全离线运行 | ASR / LLM 依赖云端；本地 TTS 只作为降级，不承诺全离线 |
| iOS 首版同步交付 | 见 B1；iOS 是否做取决于用户是否真的用 iPhone 练 |
| 公开上架与商店合规运营（MVP 阶段） | 先用真机侧载/内测包跑通；上架是后续可选项，不作为验收前提 |
| B2B/企业版/家校管理 | 与个人自用无关 |

【依据：调研结论 + 推理；非目标是本项目的"防膨胀清单"】

## 4. 核心体验

### 4.1 体验流程

```text
打开 App
  ↓
首页：今日场景（2 选 1）+ 本周进度 + 上次未解决的 1 个表达
  ↓
场景卡：角色/目标/3–5 个目标表达（可跳过，可预听）
  ↓
对话页：AI 开场 → 用户按住说 → AI 短回复 + 一个追问 → 循环 8–12 回合
  ↑↓ 随时可用：翻译开关 / 重听 / 慢速 / 提示阶梯 / 换话题
  ↓
结束：1 个亮点 + 最多 3 条改法 + 2 个表达 + 1 个下次建议
  ↓
复盘：听原句 vs 改进句 → 跟读一遍（可选）→ 保存到表达本
  ↓
下次：再练一次 / 换场景
```

### 4.2 一次 10 分钟的完整体验（Happy Path）

| 时间 | 发生什么 | 设计意图 |
|---|---|---|
| 0:00–0:30 | 打开首页，看到"会议澄清"场景和本周 1/3 次 | 降低选择成本 |
| 0:30–1:00 | 场景卡：3 个目标表达，可试听；直接开始 | 给一点点准备，但不强制 |
| 1:00–2:00 | AI 以同事身份开场，用户说第一句 | 第一句必须容易，先建立信心 |
| 2:00–6:00 | 8–12 回合；用户卡住时用一次"关键词"提示、一次"中→英" | 验证提示阶梯 |
| 6:00–7:30 | 点开 1 条纠错，听改进句；继续对话 | 纠错不打断，但可展开 |
| 7:30–9:00 | 结束：1 个亮点 + 2 条改法 + 2 个表达 | 收口，避免信息过载 |
| 9:00–10:00 | 保存 2 个表达；看到"下次再练一次" | 形成闭环 |

### 4.3 设计原则

1. **先开口，再完美**：第一句必须简单；AI 不纠正到用户不敢说。
2. **一人一句，短回合**：AI 每次最多 2 句、约 35 词，只问 1 个问题。
3. **不打断，但可展开**：默认不打断；每条用户消息旁有"纠错笔"，想看再看。
4. **提示是阶梯，不是答案**：先重听/慢速，再关键词，再参考回答，最后中→英。
5. **翻译是开关，不是默认**：默认关闭；点按翻译；字幕可开关。
6. **课后只留 1 个重点**：最多 3 条改法，避免"复盘变第二堂课"。
7. **本地优先、单用户**：不做账号、不做支付、不做社交。
8. **能力可替换**：语音识别、朗读、模型都通过抽象层接入，任一环节挂掉不拖垮整条链路。

【依据：调研 S22（Loora 的提示/纠错设计）、S13（Praktika 反馈易错过）、S28（多邻国不纠语法）、S45/S46（反馈时机研究）；第 8 条来自第 5 章硬约束】

## 5. 硬约束条款

以下三条由用户拍板，是**不可协商的架构前提**。任何方案如果违反，先改方案，不改约束。

### C1 模型接口由用户自填：OpenAI 兼容协议

**约束内容**
- 用户自己填 `base_url`、`api_key`、`model` 三项；不绑定任何具体厂商。
- 只依赖 OpenAI 兼容协议的最小公共子集（`POST /chat/completions`，可选用 SSE 流式）。
- 不假设存在厂商专属能力（联网搜索、内置语音、文件、函数调用）。

**对架构的影响**
- 需要一个独立的"模型接入层"，把协议差异收口在一个适配器里；业务层只认"给消息列表，返回文本 / 文本流"。
- 不能依赖任何一家 SDK 的强类型特性；用通用 HTTP 客户端 + 自写轻量协议解析。
- 必须在设置页提供**连通性自检**，否则用户填错后只会看到"对话没反应"。
- 提示词（prompt）要自己维护，不再享受厂商"开箱即用"的角色设定；场景、纠错、复盘都要靠提示词工程。
- 成本统计要用返回的 `usage` 字段做估算，且该字段可能缺失 → 需要本地 token 估算兜底。

**风险**
- 兼容≠一致：流式格式、温度范围、`max_tokens` 字段名、错误码、限流策略都可能不同（详见第 7 章）。
- 用户填入的第三方中转服务可能随时变更或失效，且不一定有 SLA。
- 不同模型的指令遵循能力差异会直接改变产品体验（例如不遵守"只问 1 个问题"）。
- 密钥保存在本机，存在被读取的风险（详见第 7.1 与 9 章）。

### C2 朗读使用免费的 Edge TTS

**约束内容**
- 默认朗读引擎为 Edge TTS（微软 Edge 浏览器"大声朗读"背后的在线语音合成）。
- 免费、不需要用户申请 Key。
- 但它是**非官方接口**，不承诺长期可用。

**对架构的影响**
- 朗读必须放在 `TtsEngine` 抽象后面，上层只调用"把这段文本变成可播放音频"。
- 合成结果要落盘缓存（文本 + 音色 + 语速 → 音频文件），减少重复请求与断网影响。
- 必须内置至少一个**不需要网络的兜底引擎**（系统 TTS），保证 Edge TTS 失效时会话还能继续。
- 音频播放要能中途取消，且取消后不能污染下一段播放。

**风险**
- 无官方授权、无 SLA、无配额承诺；可能 403、端点变更、签名算法变更、地区限制。
- 长文本合成可能被截断或延迟升高。
- 商业使用存在条款风险（本项目为个人自用，风险可控但不为零）。
- 详见第 8 章与第 10 章。

### C3 核心能力优先采用成熟开源项目

**约束内容**
- 语音识别、朗读、翻译、网络与存储等基础能力，优先用成熟开源库/现成包。
- 不自研音频编解码、不自己实现 WebSocket 协议栈、不自己训练模型。
- 只有在"现成方案明显不满足"时才写少量适配代码。

**对架构的影响**
- 技术栈以 pub.dev 上维护活跃的包为主；选包时把"许可证 + 最近更新时间 + issue 响应"作为硬指标。
- 引入任何包前先确认许可证是否与"个人自用 + 可能公开仓库"兼容。
- 抽象层很薄，只做协议转换和错误归一，不重复造轮子。

**风险**
- 部分包维护者少、更新慢，Flutter 大版本升级时可能失配（尤其涉及原生插件的录音/播放）。
- 许可证陷阱：如 Piper 为 GPL-3.0-or-later、LibreTranslate 为 AGPL-3.0、NLLB 权重为非商用许可。
- 成熟开源不等于零维护，插件层的 Android 权限/后台限制仍需自己处理。

### 5.4 三条约束共同造成的结构

```text
业务层（场景 / 对话 / 纠错 / 复盘 / 表达本）
        │
        ├── LlmClient 抽象 ──── OpenAI 兼容适配器（dio + SSE）
        ├── AsrEngine 抽象 ──── 系统识别 / whisper.cpp / sherpa-onnx
        └── TtsEngine 抽象 ──── Edge TTS / 系统 TTS / Piper
        │
本地存储（Drift + SQLite）＋ 安全存储（Key）
```

三条约束的落点都是"**在能力边界上加一层薄适配**"：换模型、换朗读、换识别都不改业务层。

## 6. 能力选型：成熟开源方案

> 说明：以下版本与维护状态为 **2026-11 查询**结果，实施前需以 pub.dev / PyPI / 仓库 LICENSE 复核；无法确认的一律标「未核实」。许可证以仓库 LICENSE 为准。

### 6.1 语音识别（ASR）

| 方案 | 形态 | 许可 | 成熟度 | 维护状态 | 个人自用适合度 | 备注 |
|---|---|---|---|---|---|---|
| `speech_to_text` | Flutter 调系统识别（Android SpeechRecognizer / iOS Speech） | BSD-3 | 高（几乎零配置） | 活跃 | ★★★★☆ 首选"先跑通" | 免费、延迟低；离线能力取决于系统；长句可能提前截断 |
| whisper.cpp（Flutter 封装 `whisper_ggml`） | 端侧 Whisper | MIT | 高（上游极活跃） | 活跃 | ★★★☆☆ 离线备选 | tiny≈75MB / base≈142MB（模型体积为约数，**未逐字节核实**）；中端机实时率待实测 |
| sherpa-onnx（`sherpa_onnx`） | 端侧流式 ASR | Apache-2.0 | 高 | 活跃 | ★★★☆☆ 流式备选 | 支持流式识别，接入复杂度高于 whisper.cpp |

| Vosk | 端侧/轻量 | Apache-2.0 | 中 | 维护一般 | ★★☆☆☆ | 模型小、准确率低于 Whisper |
| Web Speech API | 浏览器 | 非开源 | — | — | 不适用 | 本项目不做 Web 基线 |

**为什么选它而不是自己实现**：语音识别涉及声学模型、语言模型与解码器，自研成本远超个人项目收益；`speech_to_text` 直接复用操作系统能力，whisper.cpp 提供了可离线、可审计的成熟替代，二者都能在半天内接入。

## 7. 用户自填模型的配置与差异兜底

### 7.1 配置怎么存

| 配置项 | 存储位置 | 理由 |
|---|---|---|
| `base_url` | 本地数据库（配置表） | 非敏感，需要随备份/展示 |
| `model` | 本地数据库 | 同上；允许手填，不依赖 `/models` 拉取 |
| `api_key` | **系统安全存储**（Keystore / Keychain），不落普通表 | 避免明文出现在数据库文件、日志、崩溃上报中 |
| 语音音色、语速、水平、翻译默认等 | 本地数据库 | 普通设置 |
| 是否已通过连通性校验、上次校验时间 | 本地数据库 | 用于首页提示"配置可能失效" |

**关于加密**
- 密钥用系统安全存储即可，**不需要**再对整个数据库做 SQLCipher 级加密（MVP 阶段；若后续把数据库备份到外部再评估）。
- 会话转写属于隐私数据，但价值密度低于密钥；采用"应用私有目录 + 可一键删除"，不额外加密。
- 日志中禁止输出 `api_key`、完整请求头、完整转写文本。

### 7.2 连通性怎么校验

设置页提供"测试连接"按钮，按成本从低到高依次尝试：

1. `GET {base_url}/models`（可选）：成功则展示可用模型列表，供下拉选择；失败**不视为配置错误**，因为大量兼容实现不提供该端点。
2. `POST {base_url}/chat/completions`，用 `max_tokens` 极小（如 1–8）、单条短消息做探针；返回 200 且有 `choices[0]` 即视为可用。
3. 若 2 失败但返回了可解析的错误体，直接把厂商错误信息展示给用户（例如"模型名不存在""余额不足""Key 无效"）。

**校验结果分三态**：`未校验` / `可用` / `失败（附原因）`。首页与对话页在 `失败` 时给出明确入口，而不是静默失败。

### 7.3 换模型后的行为差异怎么兜底

不同兼容实现即使都叫"OpenAI 兼容"，行为也可能不同。产品侧的兜底原则是：**能降级就降级，不能降级就明确告知，绝不假装正常**。

| 差异点 | 可能表现 | 兜底策略（需求层，不涉及实现细节） |
|---|---|---|
| 流式（SSE） | 不支持流式 / 无 `[DONE]` / `delta.content` 为空 / 夹杂心跳注释 / 返回 `reasoning_content` | 流式失败或 3 秒无首字，自动回退为**非流式整段返回**；解析时忽略未知字段与空增量 |
| 温度 | 只接受 0–1，或忽略该参数 | 统一按 0–1 发送；用户不需要理解温度 |
| 输出长度 | `max_tokens` 与 `max_completion_tokens` 支持不一 | 优先发 `max_tokens`；若报"未知参数"再去掉该参数重试一次 |
| 函数调用 / JSON 模式 | 不支持或支持不完整 | **不依赖**函数调用与严格 JSON；结构化结果（纠错、复盘）用"提示词约束 + 宽容解析 + 失败再请求一次" |
| 角色字段 | 不支持 `system`，或把 `system` 当普通消息 | 首选 `system`；失败后把系统提示合并进首条 `user` 消息重试 |
| 错误码 | 401/403/404/429/400/5xx 语义不一致；200 响应体内带 `error` | 统一归为四类：**鉴权失败 / 模型或路径不存在 / 限流 / 服务端异常**，分别给不同文案与操作建议 |
| 计费字段 | `usage` 缺失或字段不同 | 缺失时按字符数本地估算，并在成本统计中标注"估算" |
| 指令遵循 | 回复超长、一次问多个问题、跳出角色 | 提示词里加硬性约束 + 客户端截断兜底（超过长度只显示前 N 句并提示） |

**换模型后用户能感知的变化**：语速感（首字延迟）、回复长短、纠错质量。设置页提供"换模型后跑一次 3 回合自检"的入口（P1），用固定脚本快速暴露"不流式""不遵守角色"等问题。

## 8. 朗读抽象与 Edge TTS 依赖隔离

### 8.1 抽象边界

上层（对话页、复盘页、表达本）只认一个能力：

> **给定文本 + 音色 + 语速，返回可播放的音频（或播放句柄），并支持取消。**

不关心：走什么协议、是否需要网络、返回的是 MP3 还是 WAV、是否命中缓存。

### 8.2 引擎分层

| 层 | 职责 | 变化频率 |
|---|---|---|
| 业务层 | 决定"读哪句、用什么语速、何时取消" | 低 |
| `TtsEngine` 接口 | 统一合成/播放/取消/预取 | 极低 |
| Edge TTS 适配器 | WSS 协议、SSML、鉴权签名、流式分片 | 中（接口可能变） |
| 系统 TTS 适配器 | 调用端侧引擎 | 低 |
| 本地神经 TTS 适配器（可选） | Piper / Kokoro | 低 |

**替换成本**：换掉 Edge TTS 只需新增一个适配器 + 改默认引擎配置，业务层代码零改动。

### 8.3 备选与降级顺序

1. **Edge TTS**（默认）：音质最好、免费。
2. **系统 TTS**（自动兜底）：Edge TTS 连续失败（如 2 次）或超时 > 4s 时切到系统引擎，并提示一次"当前使用系统语音"。
3. **本地神经 TTS**（可选，P2）：完全离线、音色更好，但集成与包体成本高。
4. **静音降级**：全部失败时只显示文字，不阻塞对话，并在消息旁给"重试朗读"。

### 8.4 需求层要求

- 任何一句话的朗读失败，都**不得**影响这句话的文字展示与后续回合。
- 朗读缓存命中时，重听必须是"瞬时"的（不重新请求网络）。
- 用户可一键关闭自动朗读（只显示文字），该设置优先于任何引擎。
- 音色选择来自当前引擎的能力清单；切换引擎时，不支持的音色自动回落到该引擎默认音色。

> 协议、鉴权、流式与缓存的具体做法见技术文档第 5 章。

## 9. 功能需求

优先级说明：
- **P0 = 必须有**：没有它，MVP 闭环不成立。
- **P1 = 锦上添花**：第一版之后再加，能明显提升体验。
- **P2 = 以后再说**：有价值，但不影响"够用"。

### F0 模型配置与自检（P0，新增）

**做什么**
- 设置页填写 `base_url` / `api_key` / `model`；`model` 支持手填，也支持从 `/models` 拉取后选择。
- "测试连接"按钮，返回三态结果与可读原因。
- 支持保存多套配置（P1：例如"快模型""好模型"两套切换）。
- 首页在配置不可用时给出明确提示与跳转。

**验收标准**
- 三项必填项缺失时无法保存，且提示具体缺哪项。
- 测试连接失败时，能看到厂商返回的错误摘要（截断展示，不含 Key）。
- 修改配置后，下一次请求立即使用新配置。
- 杀进程重启后配置仍在；Key 不出现在任何界面明文回显（只显示尾 4 位）。

**依据**：C1 硬约束；个人自填接口必须自带"我填错了"的可诊断性。

### F1 场景库（P0）

**做什么**
- MVP 首批 2 个场景：咖啡店点单、工作会议澄清；此后持续扩容，**内置场景数量与分类以 `builtinScenarios` 实际数据为准，不设上限**（见 §0.1、§0.1.1）。
- 每个场景包含：角色、目标、难度、分类、AI 开场白、5 个目标表达、预期回合数、成功条件、1–2 个意外分支，以及 `scenario_goals.dart` 中 3 条可勾选目标。
- 独立场景库页 `/scenarios`：按实际存在的分类切换、按中英文标题搜索、显示「练过 N 次」；首页仍只放 2 张推荐卡 +「全部 N 个」入口，N 由实际数据计算。
- 场景卡可跳过；完成后标记"练过"。目标表达追加进 `chatSystem` 自然引导，不列出、不测验。

**验收标准**
- 从首页到开始对话 ≤2 次点击；从场景库到场景详情 1 次点击。
- 场景卡上的目标表达可以试听（走 TTS 抽象，失败时降级为文字）。
- 对话结束后，场景被标记为"练过"，并记录次数；清空数据后计数归零。
- 场景库分类与搜索结果正确，无结果时显示空态。

**依据**：调研中场景型产品（Speak/ELSA/Praktika/Loora/可栗）的共同做法；推理：场景比开放话题更容易开口。

### F2 语音对话回合（P0）

**做什么**
- 按住说话（push-to-talk）、松开提交；显示识别文本；可重说、可改用文字。
- AI 回复英文，最多 2 句/约 35 词，包含 1 个追问；TTS 播放。
- 可重听 AI 消息、可停止播放；MVP 不做"打断 AI 说话"（barge-in）。
- AI 保持角色，不跳出场景；用户跑题时，温和拉回目标一次。
- 录音与播放互斥：播放中不能录音（需先停止），录音中不播放。

**验收标准**
- 一次会话能连续完成 ≥8 回合，不出现"AI 不知道说什么"的死局。
- AI 单次回复不超过 2 句；不会一次问 2 个问题。
- ASR 识别错误时，用户可以在 10 秒内改文字并继续。
- 首段语音延迟 p50 ≤1.5s、p95 ≤3s（目标值；以"松开手指 → 听到 AI 首字"计）。
- 用户说"I don't understand"时，AI 会用更简单的话重说，而不是重复原句。
- 耳机/蓝牙切换后，下一次播放仍从耳机出声，不"漏音"到扬声器。

**依据**：调研中主流 AI 对话均为短回合；延迟经验值 S47/S48；推理：文字兜底能解决口音/噪音导致的识别失败。

### F3 翻译开关（P0）

**做什么**
- 三种状态：**关闭（默认）** / **点按翻译** / **常开双语字幕**。
- "点按翻译"：点 AI 的某条消息，显示中文；不自动朗读中文。
- "常开"：AI 消息下方显示中文；英文仍是主显示。
- 独立的"我想说"救生圈：输入中文 → 给一句英文建议；用户可编辑、可试听，但**不自动发送**。
- 结束复盘用中文解释"为什么这样改"。
- 翻译与对话复用**同一个模型配置**（Base URL / 模型 / 密钥），不设独立翻译模型；AI 气泡与提示气泡都可点按翻译。
- 提示结果（L2–L4）在英文提示下方显示中文对照；提示气泡同样可显示中文。

**验收标准**
- 翻译状态在本次会话内保持；重开 App 后回到默认"关闭"或上次设置（待拍板）。
- 关闭时，气泡内不出现中文翻译（设置/帮助、提示结果的中文对照除外）。
- 气泡操作行：「重听 / 停止」靠左、「中文 / 翻译中…」靠右，中间弹性空白分隔，不叠放、不误触。
- "我想说"返回 1 句可直接说的英文；用户必须自己按下说话或点"发送"，不会自动替用户回答。
- 翻译不会自动播放中文语音。
- 翻译请求失败时，英文原文仍可读，并给"重试翻译"；失败原因与对话链路无关（同一模型配置）。

**依据**：Loora 的 CC/翻译/慢速 S22；多邻国"不纠语法保流畅" S28；推理：听力目标要求"先听再看"。

### F4 分级提示（P0）

**做什么**
- 提示按钮始终可用，按阶梯展开：
  - **L1 重听/慢速**：不给答案，只重复 AI 的话或放慢。
  - **L2 关键词/句型**：给 3–5 个词或一个句型，不给完整句。
  - **L3 参考回答**：给 1 句完整英文；用户要自己说出来，不自动发送。
  - **L4 中→英**：输入中文，给英文；可编辑后再说。
- 不设硬性次数限制（个人自用）；记录使用次数。
- 用了 L3/L4 的回合，在复盘里标记"有辅助"，建议再练一次。

**验收标准**
- 任何一级提示都不会自动替用户发送回答。
- 提示出现后，AI 等待用户开口，不会自顾自继续。
- 复盘显示本次提示次数；用 L3/L4 的回合能被识别。
- L2 不泄露完整答案；L3 只给 1 句，不给段落。
- L1 在朗读不可用时，仍能给出"慢速文字 + 可重试音频"。
- 提示结果卡同时显示英文提示与一行中文对照；常规路径由同一次旁路请求返回（`EN:` / `ZH:` 两行），L4 可直接复用用户输入的中文；仅当模型未按两行格式输出时才补一次翻译请求，补翻失败不影响英文提示。
- 提示气泡（历史/续练数据）也支持点按翻译与常开字幕。

**依据**：Loora 灯泡/救生圈 S22；Praktika 智能提示 S11；推理：直接给答案会形成依赖。

### F5 纠错与复盘（P0）

**做什么**
- **默认温和模式**：每条用户消息旁出现一个小标记；点开看该句的纠错（语法/用词/发音提示）。对话不中断。
- **课后总结**（中文）：
  - 1 个做得好的点（具体，不空泛）。
  - 最多 3 条改法：原句 → 更好的说法 → 为什么（≤25 字）。
  - 2 个可复用表达（场景相关）。
  - 1 个下次建议。
- 每条改法可试听"更好的说法"；可保存到表达本。
- 不做分数、不做排名。
- 纠错结果是"模型输出"，必须容错：解析失败时不展示半成品，而是给"本次未能生成总结，可重试"。

**验收标准**
- 课后总结不超过 1 屏；改法最多 3 条。
- 每条改法都有"原句/改进句/原因"，原因用中文。
- 每条改进句可播放音频。
- 用户可以删除不认同的改法；删除后不影响会话记录。
- 默认模式下，AI 不会在对话中打断用户纠错。
- 模型返回不符合结构时，App 不会崩溃或展示乱码。

**依据**：Loora 的"标记 + key takeaway" S22；Praktika 缺课后总结导致反馈易错过 S13；ELSA 课后四维反馈 S7；反馈时机研究 S45/S46；推理：3 条是个人可消化的上限。

### F6 会话记录与表达本（P0）

**做什么**
- 本地保存每次会话：日期、场景、时长、回合数、提示次数、翻译次数、完整转写。
- 转写中保留纠错标记；可点开看详情。
- 表达本：保存课后总结里的表达，或对话中长按保存；显示来源场景；可试听。
- MVP 只做"列表 + 可试听"；"随机抽 5 条复习"放 P1。

**验收标准**
- 杀进程重启后，历史记录、表达本仍在。
- 可以回看任意一次会话的转写和纠错。
- 表达本按时间倒序；可删除；可试听。
- 不要求登录；数据只在本机应用私有目录。
- 提供"删除本次会话"与"清空所有数据"。

**依据**：Loora 保存词汇 S22；Praktika 可保存但不能复习被吐槽 S13；推理：个人自用先解决"存得住、找得到"。

### F7 设置（P0）

**做什么**
- 模型配置（见 F0）。
- 朗读引擎：Edge TTS（默认）/ 系统 TTS；音色、语速。
- 水平：A2 / B1 / B2（影响 AI 用词、语速、句子长度）。
- 纠错模式：温和（默认）/ 严格（P1）。
- 翻译默认：关闭 / 点按 / 常开。
- 输入方式：语音优先 / 文字优先。
- 单次目标时长：5 / 10 / 15 分钟。
- 自动朗读开关。

**验收标准**
- 设置修改后，下一回合生效。
- 设置持久化；有"恢复默认"（不含模型配置，防止误删 Key）。
- 水平设置会实际影响 AI 回复长度/用词（不能只是存值）。
- 切换朗读引擎后，音色列表随之变化并给出默认音色。

**依据**：Speak 的语速/字幕 S2；Praktika 的 Soft/Balanced/Strict S11；推理：个人自用需要"按当天状态调难度"。

### F8 坚持机制（P0，极简）

**做什么**
- 首页显示：本周已练 X/3 次、累计 Y 分钟、连续 Z 天。
- 完成后给一句具体反馈（"今天你用了 3 个新表达"），不发勋章。
- 不做排行榜、不做社交分享、不做复杂任务体系。
- 本地提醒（P2）。

**验收标准**
- 周计数按自然周重置；跨周不丢历史。
- 连续天数按"有完成一次 ≥5 分钟会话"计算。
- 不出现"必须打卡才能解锁"的强制机制。

**依据**：多邻国强习惯但弱口语 S31；推理：个人自用只需要"看见自己练过"，不需要游戏化压力。

### F9 自定义场景（P1）

**做什么**
- 表单：场景名、AI 角色、目标、3 个目标表达、难度。
- 保存前可预览 AI 开场白；开始后按自定义场景走。
- 可编辑/删除。

**验收标准**
- 自定义场景和内置场景在对话页表现一致。
- 预览不消耗会话次数。
- 删除场景不影响历史记录。

**依据**：ELSA 支持自定义角色扮演 S7；TalkPal 多场景 S16；推理：个人真实需求会变化，后期需要自定义。

### F10 发音反馈（P2）

**做什么（如果以后做）**
- 只标"可能听不清"的词，不给总分；可点击听标准发音。
- 不做音素级评分、不做排行榜。

**为什么不做进 MVP**
- 评分准确性争议大；容易引发"刷分"而不是交流；个人目标不是考试。
【依据：ELSA 评分准确性差评 S9；Speak 反馈浅 S4】

### F17 每日打卡（P0，2026-11-13 用户拍板）

**做什么**
- 首页新增「今日」主卡：今日打卡状态（已打卡 / 待打卡）+ 连续天数（沿用 F8 口径，含手动补记）+ 当日学习构成（口语 / 轻量 / 听写 / 背单词 / 影子跟读，已做的亮起、点按可补记）+ 目标进度（今日分钟 / 目标、本周次数）+ 入口（未打卡→开始今日学习；已打卡→查看日历）。
- 新增 `/checkin` 打卡日历页（挂在 ShellRoute 外，不改底部 4 Tab）：月度网格点亮已打卡天、点击看每日明细、顶部统计本月打卡 / 当前连续 / 最长连续；纯本地、断网可看。
- 手动补记：用户可在首页或日历把 App 外的学习（背单词 / 影子跟读 / 其它）勾选进当天，断网、无模型密钥也能记；自动打卡（口语 / 轻量 / 听写）仍由 session / 听写表按天聚合，不另起统计。

**边界（沿用 F8 红线）**
- 不做连胜 / 勋章 / 排行榜 / 每日推送 / 分数等级；日历只展示"哪天练了、练了什么"，不发放徽章、不排名、不弹通知。
- "督促"靠首页常驻的"今日待打卡"状态 + 连续天数自然实现，无需提醒。
- 新增 `daily_checkin` 表只存手动补记；自动活动由既有表聚合，连续天数口径与 F8 一致（有效练习 ∪ 手动补记，按自然日去重）。

**依据**：用户长期学英语需要"输入→吸收→输出"闭环；多邻国习惯强但口语弱 S31；背单词 / 影子跟读是用户明确的补充诉求（2026-11-13 对话）。

### F16 学习路径（P1，2026-11-13 用户拍板启用）

**做什么**（完整口径见 §0.4 与 `design-learning-path-v0.1.md`）

- 首次 3 问定起点（水平、目标场合 + 具体诉求、投入节奏），按起点与目标动态生成四阶段计划；每阶段给出学习目标、内容范围、推荐顺序与完成标准，阶段内 5–7 条可直接点开的轻量安排。
- 路径页回答「我在哪 / 走到哪了 / 接下来做什么」；阶段回顾给「进入下一阶段 / 再巩固一轮 / 换目标重排」三个出口与三条可解释证据。
- 首页「下一步」卡给一句可核对的理由 + 一键开始 + 换一个 / 今天先跳过 / 查看路径；复盘末尾给「下一次练这个」；场景库加「适合当前阶段」提示；断档回归与低能量日有入口。
- 生成、重排、完成判定全部为可见可解释的本地规则，不新增模型调用、不新增联网依赖、不新增内容库。

**验收标准**见 §0.4「验收标准（本次新增，不替代 §10.2）」8 条。

**依据**：调研报告 §1.2 断点 A / C / D、§5 借鉴项 #3 / #5 / #10、§7 建议路线；用户 2026-11-13 拍板。

## 10. MVP 范围与验收

### 10.1 MVP 包含（P0）

| 模块 | 包含 | 不包含 |
|---|---|---|
| 平台 | Flutter Android（真机可装） | iOS 同步适配 |
| 配置 | base_url / api_key / model + 测试连接 | 多套配置切换 |
| 场景 | MVP 首批 2 个；内置场景以 `builtinScenarios` 实际数据为准 + 场景库页（分类/搜索/练过次数），见 §0.1、§0.1.1 | 场景市场、随机话题 |
| 对话 | 按住说话 + 文字兜底、短回合、重听、停止播放 | 全双工打断、多人对话、视频 |
| 翻译 | 关闭/点按/常开；"我想说"中→英 | 自动翻译所有消息、离线翻译 |
| 提示 | L1–L4 阶梯 | 个性化"你可能会说"提示 |
| 纠错 | 温和模式、每条可展开、课后 1+3+2 | 严格模式、发音分数、语法课程 |
| 朗读 | Edge TTS + 系统 TTS 兜底 + 本地缓存 | 本地神经 TTS |
| 记录 | 本地历史、转写、表达本 | 云端同步、多端、分享 |
| 设置 | 引擎/音色/语速/水平/翻译默认/输入方式/时长 | 多口音多语言 |
| 坚持 | 本周次数/分钟/连续天数 | 排行榜、社交、勋章、推送（P2） |

### 10.2 MVP 验收清单

- [ ] 在 Android 真机上完成一次"配置模型 → 选场景 → 对话 → 复盘 → 保存"的完整闭环。
- [ ] 语音输入失败时，能改用文字继续，不需要重开会话。
- [ ] 翻译关闭时，界面没有中文翻译；点按后能看到中文；不会自动朗读中文。
- [ ] 提示 L1–L4 都能用；任何一级都不会自动发送答案。
- [ ] 课后总结最多 3 条改法，每条有原句/改进句/原因/音频。
- [ ] 杀进程重启后历史、表达本、设置仍在；Key 不以明文出现在界面。
- [ ] 一次会话 ≥8 回合，AI 每次 ≤2 句且只问 1 个问题。
- [ ] 首段语音延迟达到 p50 ≤1.5s、p95 ≤3s（本地网络，目标值）。
- [ ] 手动把朗读引擎切成系统 TTS，会话仍完整可用。
- [ ] 单次会话成本可统计（含"估算"标记），且不超过设定上限。
- [ ] 不出现账号、支付、社交入口。

### 10.3 MVP 明确不做

- 不做课程体系、不做考试题库、不做真人外教。
- 不做发音总分、不做音素级评分、不做排行榜。
- 不做虚拟人/视频/全双工。
- 不做支付/订阅/账号/云端同步。
- 不做多语言、不做完全离线、不做公开上架运营。

【依据：第 3.3 节非目标 + 个人自用取舍】

## 11. 后续迭代方向

### MVP（对应 v1 内部版本）
- MVP 首批 2 个场景（此后持续扩容，当前口径见 §0.1、§0.1.1）、按住说话、翻译开关、L1–L4 提示、温和纠错、课后总结、本地历史、表达本、基础设置、周计数、模型配置与自检。
- 目标：验证"10 分钟闭环"在真机上是否真的能坚持。

### v0.2（复盘与个性化）
- 严格模式（AI 先 recast 再继续）。
- 表达本复习模式：随机抽 5 条、听音复述、标记"已掌握"。
- 自定义场景。
- 周报：本周练了几次、最常犯的 1 个问题、下周建议。
- 目标：让"练过"变成"记住"。

### v0.3（真实感与难度）
- 第二批场景：工作寒暄/站会、旅行求助。
- 英音/澳音（按需，取决于 TTS 引擎能力）。
- 场景分支：AI 根据用户回答增加意外追问。
- 语速自适应：根据用户水平动态调整。
- 目标：减少"背台词感"，接近真实对话。

### v1.0（可选，不一定做）
- iOS 适配（若用户确实使用 iPhone）。
- 本地神经 TTS（Piper / Kokoro）作为离线朗读选项。
- 云端同步（如果确实多设备）。
- 发音"可理解度"提示（不做分数）。
- 目标：只在"确实影响坚持"时才做。

> **四期独立成线（2026-11-13 用户拍板）：轻量学习路径**，见 §0.4 / F16 与 `design-learning-path-v0.1.md`；目标是把「练完一次」的闭环延长成「练完一个月」的方向感，不做课程、不做测评分、不做推送。任务与验收见 `milestones-phase4-learning-path-v0.1.md`。
>
> 二期独立成线：视频教材导入与单句听写，不进 MVP，详见第 12 章。

## 12. 二期：视频教材导入与单句听写（不进入当前 MVP）

> **定位**：独立的二期功能线，与 MVP 的"场景对话"并列。**不改变第 10 章的 MVP 范围与验收标准**，也不影响第 8 章的里程碑。
> **预研**：[视频教材导入与单句听写：开源方案预研](research-video-material-dictation-2026-11.md)
> **一句话**：把一段真实语速的音视频变成可逐句练的教材，用户听一句、写一句、当场知道差在哪。

### 12.1 要解决的问题

MVP 练的是"说"，二期补的是"听"。当前缺口的本质不是"没有听力材料"，而是：

1. **材料不可控**：找到的视频要么没字幕、要么字幕断句很粗，没法按句练。
2. **听完不知道自己漏了什么**：泛听一小时，不如精听十句；但没有工具把"漏词"指出来。
3. **反复倒带成本高**：手动拖动进度条找一句话，比听写本身还累。
4. **材料与练习脱节**：收藏了一堆视频，没有"练到哪、错在哪"的记录。

【依据：推理 + 市面听写类工具的通行做法（预研第 4 章）】

### 12.2 目标

1. **把用户已有的音视频变成句子级教材**：切句、对齐、可逐句播放，不依赖平台提供的时间轴。
2. **单句听写闭环**：听 → 写 → 判 → 看差异 → 复听 → 收藏，单句 10–20 秒完成。
3. **进度可追踪**：哪集练到第几句、哪些句子反复错。
4. **合规可控**：默认只处理用户本地文件，App 不主动抓取、不分发素材。

### 12.3 明确不做（二期也不做）

| 不做 | 原因 |
|---|---|
| 内置视频网站下载器 / 批量爬取 | 平台条款与版权风险最高；技术上也会被风控反复打断 |
| 素材分享、导出、教材市场 | 一旦向他人提供，性质从"个人使用"变为"传播" |
| DRM 解密、加密流媒体处理 | 违法风险，且技术上不可维护 |
| 在线视频流媒体播放器（替代 B 站/BBC 客户端） | 与产品目标无关，成本极高 |
| 逐词卡拉 OK 高亮、音素级发音评分 | 需要音素级对齐，收益低于成本；且与"听写"目标不一致 |
| 自动生成课程、AI 讲解视频 | 范围膨胀；二期只做"练" |
| 多语言素材（只做英语） | 与 MVP 的非目标一致 |

### 12.4 典型使用流程

**流程 A：本地文件 + 自带字幕（二期主路径）**

```text
教材库 → 导入
  → 选本地视频/音频 + 字幕文件（.srt / .vtt）
  → 解析：切句、校准时间轴、去重、过滤音乐行
  → 教材详情：共 N 句 / 预计 M 分钟
  → 开始听写：只听音频，不看字幕
      听一句（可 0.75x、可无限复听）
      → 输入（键盘或语音）
      → 判分：逐词标出 漏写/多写/拼错
      → 看答案、复听、存进表达本
      → 下一句
  → 结束：正确率、错句列表、只练错句
```

**流程 B：无字幕，自动生成（二期第二阶段）**

```text
导入音视频 → 抽音轨 → ASR（带词级时间戳）→ 切句 → 允许手动合并/拆分/微调
  → 之后同流程 A
```

**流程 C：链接导入（可选，默认关闭，需用户显式确认）**

```text
粘贴单集链接 → 提示版权与条款风险 → 用户确认"我有权使用"
  → 由外部预处理（不在 App 内跑下载）产出素材包 → 导入
```

### 12.5 必须有的能力

#### F11 教材导入与解析（二期 P0）

**做什么**
- 支持本地视频/音频文件 + 字幕文件（`.srt` / `.vtt`）导入。
- 解析进度可见；失败给具体原因（格式不支持 / 字幕编码错误 / 无音轨）。
- 无字幕时提示"可自动生成字幕（耗时较长）"。
- 素材与原始文件分开存放：只保留抽取出的音频片段与文本，不复制整个视频（除非用户选择保留画面）。

**验收标准**
- 导入一集 10 分钟素材，解析在 60 秒内完成（本地、有字幕）。
- 字幕编码为 GBK/UTF-8 时都能正确读取，不出现乱码。
- 解析失败时，用户能看到原因并知道下一步做什么。
- 同一素材重复导入时，提示"已存在"而不是产生副本。

**依据**：预研第 2、3 章；本地文件是合规风险最低的入口。

#### F12 句子切分与对齐（二期 P0）

**做什么**
- 按标点切句，目标 3–12 秒 / 5–22 词；过短合并、过长在逗号/连词处再切。
- 每句带起止时间；前后留 80–150ms 余量。
- 提供手动修正：合并相邻句、拆分一句、微调起止点。
- 过滤纯音乐、掌声、`[Music]`、纯标点行。

**验收标准**
- 自动切分后，需要人工修正的句子 ≤10%。
- 任意一句都能被单独播放，且首尾不被明显切掉。
- 手动修正后，进度与时间轴立即生效，不需要重新解析。

**依据**：预研 4.1；断句质量直接决定听写体验。

#### F13 单句听写（二期 P0）

**做什么**
- 默认只播音频、不显示字幕；每句可无限复听、可 0.75x。
- 输入方式：键盘优先，语音输入作为可选（复用 MVP 的 ASR）。
- "显示答案"前不泄露原文；提示只给"这句有几个词"这类弱提示。
- 支持上一句/下一句/标记"这句太难"。

**验收标准**
- 从进入听写到开始听第一句 ≤2 次点击。
- 复听不产生网络请求（本地音频）。
- 语音输入识别失败时，能无缝切回键盘，输入内容不丢。
- 中途退出再进入，回到上次的句子。

**依据**：推理 + 预研 4.2。

#### F14 判分与差异反馈（二期 P0）

**做什么**
- 规范化后做词级 diff：忽略大小写、标点、多余空格；数字与英文单词双向等价；缩写（`I'm` / `I am`）可配置为等价。
- 逐词标出：正确 / 漏写 / 多写 / 拼错；拼写容错仅对长词（≥6 字母）放宽 1 个编辑距离。
- 给一个可解释的正确率，而不是黑箱分数；阈值可调（默认 90% 通过）。
- 不通过时优先展示"差在哪"，不直接给整句答案。

**验收标准**
- 大小写、标点不同不判错。
- 漏一个词时，能准确指出漏的是哪个位置。
- 同义改写（如 `I would like` vs `I'd like`）按配置处理，且规则对用户可见。
- 判分不依赖网络与模型，离线可用。

**依据**：预研 4.3；用模型判分会带来成本、延迟与不一致。

#### F15 教材库与复练（二期 P1）

**做什么**
- 教材列表：标题、时长、句数、已练句数、正确率。
- 单集详情：句子列表 + 状态（未练 / 已通过 / 有错）。
- 错句本：跨教材汇总错句，可只练错句。
- 删除教材时级联删除片段与进度；提供"清理音频缓存"。

**验收标准**
- 重启后进度、错句本仍在。
- "只练错句"能正确筛选，且顺序稳定。
- 删除教材后，相关音频文件确实被清理。

**依据**：F6 表达本的产品逻辑复用；预研第 6 章。

### 12.6 与 MVP 的复用关系

| 复用 | 来自 MVP | 说明 |
|---|---|---|
| 语音识别 | `AsrEngine` | 听写可用语音输入；无字幕时也用同一条链路做转写 |
| 朗读 | `TtsEngine` | 答案示范、生词发音；失败仍可降级系统 TTS |
| 翻译 | 翻译旁路 | 点按看中文，默认关闭 |

## 14. 风险与降级路径

### 14.1 硬约束带来的新增风险

| 风险 | 表现 | 降级路径 |
|---|---|---|
| OpenAI 兼容层不一致 | 流式无输出、参数报错、回复超长、角色跑偏 | 流式失败转非流式；参数报错去参重试；超长客户端截断；角色跑偏用提示词加强 + 重试一次 |
| 用户填错接口 | 一直"转圈"或报错不可读 | 设置页强制"测试连接"；错误归为四类给明确文案；首页常驻配置状态 |
| 第三方中转服务失效 | 昨天能用今天不能 | 配置可快速替换；历史记录不依赖接口；离线仍可回看与复习 |
| Edge TTS 失效 | 403 / 签名变更 / 地区限制 / 超时 | 连续失败自动切系统 TTS；提示一次；保留"重试朗读"；长期方案接本地神经 TTS |
| Edge TTS 条款与稳定性 | 无 SLA、可能被限流 | 个人自用 + 缓存 + 不批量请求；不把它作为唯一路径 |
| 插件维护风险 | Flutter 升级后录音/播放插件编译失败 | 选活跃包；锁定版本；录音/播放各自只依赖一个包，便于替换 |
| 许可证风险 | GPL/AGPL/非商用权重混入 | 选包时记录许可证；Piper、LibreTranslate、NLLB 默认不引入 |
| 密钥泄露 | Key 出现在日志/截图/备份 | 安全存储 + 日志脱敏 + 界面只显示尾号 |

### 14.2 产品与体验风险

| 风险 | 表现 | 对策 |
|---|---|---|
| 延迟破坏对话感 | AI 半天不回，用户出戏 | 回合制、短回复、流式 TTS、缓存常用语音；首段延迟目标 p50 ≤1.5s |
| ASR 识别不准 | 口音/噪音导致转写错误，用户重复说 | 显示转写、可编辑、文字兜底、重说按钮；不把识别错误算作用户的错 |
| AI 过度帮忙 | 一直给答案，用户变成跟读 | 提示分级；L3/L4 必须用户自己说；复盘标记"有辅助" |
| 反馈质量不稳定 | 改错、解释太泛、打击信心 | 限制每次最多 3 条；每条必须有原句/改进句/原因；用户可删除不认同的改法 |
| 成本失控 | 长对话消耗 token | 限制 AI 回复长度、单次时长；统计每次成本；设月度上限提示 |
| 难以坚持 | 新鲜感过后不用 | 10 分钟低门槛、周目标 3 次、首页显示"上次卡在哪"；不做强制打卡 |
| 范围膨胀 | 想加课程、社交、发音分数 | 以第 3.3 节非目标为准；新功能先问"是否影响 4 周坚持" |
| 隐私 | 语音/转写包含个人信息 | 本地存储；密钥加密；提供删除入口 |

【依据：调研差评 + 硬约束 C1/C2 + 推理】

### 16.2 术语

- **回合（turn）**：用户说一次 + AI 回一次。
- **L1–L4 提示**：重听/慢速 → 关键词/句型 → 参考回答 → 中→英。
- **温和模式**：对话中不打断，只做标记；课后集中反馈。
- **严格模式**：AI 在继续对话前，先用 recast 方式重述正确说法。
- **recast**：不直接说"你错了"，而是用正确说法回应一次。
- **表达本**：保存下来的可复用短语/句子，带来源场景和音频。
- **barge-in**：用户说话时打断 AI 播放；MVP 不做。
- **OpenAI 兼容**：只保证 `POST /chat/completions` 这一最小公共协议。
- **TTS 抽象**：把"文本 → 音频"的能力与具体供应商解耦的接口层。
