## 1. 结论摘要

| # | 结论 | 理由一句话 |
|---|---|---|
| 1 | Flutter stable + **Android 优先**，`minSdk 24` / `targetSdk 36` | 个人自用先在一个平台跑通；iOS 待确认 |
| 2 | 状态管理用 **Riverpod**，存储用 **Drift + flutter_secure_storage** | 一个是当前主流且类型安全，一个能给出可迁移的 SQL 与安全的 Key 存放 |
| 3 | 录音 `record`、播放 `just_audio` + `audio_session` | 维护活跃、支持 PCM16 单声道与音频焦点/路由 |
| 4 | 识别基线用 **系统语音识别**，端侧 Whisper 作为备选/兜底 | 系统识别零配置、延迟低；国内 ROM 可能缺失，必须留端侧方案 |
| 5 | 模型层：**dio + 自写 OpenAI 兼容薄客户端**（SSE） | 不绑定厂商；约 300 行覆盖流式/取消/重试 |
| 6 | 朗读层：**`TtsEngine` 抽象 + Edge TTS 适配器 + 系统 TTS 兜底 + 本地缓存** | Edge TTS 免费好听但非官方，必须可替换 |
| 7 | 数据全部本地，**单库 SQLite**；Key 单独进 Keystore | 无账号、无云端；密钥不落普通表 |
| 8 | MVP 不做后台运行、不做全双工打断 | 后台录音不可靠；按住说话已够用 |
| 9 | 里程碑第一个可验收点是 **M1：真机跑通一次完整语音对话** | 尽早暴露权限、音频、网络三类硬问题 |

## 2. 技术选型与依据

### 2.1 Flutter 版本与目标平台

| 项 | 选择 | 依据 | 替代方案 |
|---|---|---|---|
| Flutter | 3.47.8 stable（Dart 3.13.7），2026-10-23 查询 | 稳定通道、生态兼容性最好 | `beta` 通道：不用于个人长期项目 |
| Android | `compileSdk 36` / `targetSdk 36` / `minSdk 24` | 覆盖主流在用机型；24 以上对录音与音频焦点支持完整 | `minSdk 21`：老机型适配成本高、收益低 |
| iOS | **首版不做**，代码层不刻意阻断 | 需要 Mac、签名与音频权限额外调试；见需求 Q1 | 与 Android 同步做：里程碑会翻倍 |
| 桌面/Web | 不做 | 用户已明确"不做网页版基线" | — |

**Android 优先带来的具体影响**
- 权限模型、前台服务、音频焦点按 Android 设计；iOS 分支不预先写抽象。
- 机型碎片是主要风险：国产 ROM 常缺 Google 语音服务、后台限制更激进，因此识别与朗读都必须有"不依赖系统服务"的备选。
- 发布方式：直接装 APK（`flutter build apk --release`），不做商店合规。

### 2.2 状态管理

| 方案 | 版本/许可 | 维护 | 结论 |
|---|---|---|---|
| `flutter_riverpod` | 3.4.3 / MIT | 活跃 | **采用** |
| `flutter_bloc` | 9.1.1 / MIT | 活跃 | 备选；样板代码更多 |
| `provider` | 6.1.5+1 / MIT | 活跃 | 过于基础，复杂状态要自己拼 |
| `setState` + InheritedWidget | 内置 | — | 只适合单页，不适合跨页会话状态 |

**为什么是 Riverpod**
- 对话链路天然是"多个异步状态源"（录音状态、识别结果、流式文本、播放状态、计时器），`AsyncNotifier` + `StreamProvider` 能直接表达，不需要自己写事件总线。
- 依赖注入与测试替身容易：可以把 `LlmClient` / `AsrEngine` / `TtsEngine` 在 Provider 层替换成 Fake，便于在没有网络时调试 UI。
- 编译期安全，不依赖 `BuildContext` 生命周期。

**状态划分建议**（不写代码，只定边界）

| 状态域 | 归属 | 生命周期 |
|---|---|---|
| 配置（模型/音色/水平） | 全局 Provider（读数据库） | App 级 |
| 当前会话（消息列表、回合、计时） | 会话 Notifier | 进入对话页 → 结束 |
| 录音/识别/播放瞬时状态 | 会话内的子状态机 | 单回合 |
| 首页统计 | 派生 Provider（查库） | 每次进入刷新 |

### 2.3 本地存储

| 用途 | 选择 | 版本/许可 | 理由 | 替代 |
|---|---|---|---|---|
| 结构化数据 | `drift` + `sqlite3_flutter_libs` | 2.35.3 / MIT | 类型安全、支持迁移、可写复杂查询（周统计、按场景聚合） | `sqflite`（无类型安全）、`isar`（维护状态需复核） |
| 键值/轻量设置 | `shared_preferences` | 2.5.x / BSD-3 | 启动早期就要读的开关（如主题、是否首次启动） | 全放数据库也可，但启动多一次 IO |
| 密钥 | `flutter_secure_storage` | 11.2.0 / BSD-3 | Android 走 Keystore/EncryptedSharedPreferences | 自己加密再存 → 造轮子且易错 |
| 文件路径 | `path_provider` | 2.1.x / BSD-3 | 应用私有目录，卸载即清理 | — |
| 音频文件 | 应用私有目录下的 `tts/`、`recordings/` | — | 不进数据库 BLOB（避免库膨胀、便于清理） | 存 BLOB：备份/迁移代价大 |

**为什么不用 SQLCipher**：`sqlcipher_flutter_libs` 已处于 EOL 状态（2026-11 查询），且个人自用场景下整库加密的收益低于维护成本。密钥单独进安全存储即可，见 6.4。

### 2.4 录音与播放

| 能力 | 包 | 版本/许可 | 维护 | 说明 |
|---|---|---|---|---|
| 录音 | `record` | 7.1.2 / BSD-3 | 活跃 | 支持 `AudioEncoder.pcm16bits`、16kHz 单声道、`startStream` 取实时 PCM |
| 播放 | `just_audio` | 0.10.6 / MIT | 活跃 | 支持文件/字节流、播放速度、精确 seek、播放完成回调 |
| 音频会话 | `audio_session` | 0.2.4 / MIT | 活跃 | 统一音频焦点、耳机/蓝牙路由、被其他 App 抢占时的回调 |
| 权限 | `permission_handler` | 13.0.2 / MIT | 活跃 | `Permission.microphone` |
| 防熄屏 | `wakelock_plus` | 1.8.2 / BSD-3 | 活跃 | 对话页保持常亮 |

**为什么不用 `flutter_sound`**：功能全但体量大；且 10.x 版本转向 GPL 许可（需以仓库 LICENSE 复核），与"个人自用 + 可能开源"冲突。

**播放器选型细节**
- Edge TTS 返回 MP3 分片，MVP 策略是"整段下完再播"，`just_audio` 的 `setFilePath` 足够。
- 若要做"边下边播"，用 `just_audio` 的自定义 `StreamAudioSource`，但 `Content-Type`/长度未知时部分机型 seek 会异常 → 列为 M2 优化项，不进 M1。

### 2.4.1 语音识别（ASR）引擎

识别与对话模型**配置完全分离**（`asr.*` 与 `llm_profile.*` 各自保存），互不覆盖。

| 引擎 | 协议 | 默认/开启 | 说明 |
|---|---|---|---|
| `HttpAsrEngine` | OpenAI 兼容 `POST /audio/transcriptions`（multipart） | 默认链路 | 默认硅基流动 `FunAudioLLM/SenseVoiceSmall`；可切 `Qwen/Qwen3-ASR-1.7B` 或 Groq `whisper-large-v3-turbo`，只改配置 |
| `SystemAsrEngine` | `speech_to_text` 系统识别 | 未配置 ASR 时兜底 | 部分国产 ROM 无识别服务，失败即降级文字 |
| `ChatAudioAsrEngine` | `POST /chat/completions` + `input_audio`(base64) | 设置内实验开关，**默认关闭** | 模型 `MiMo-V2.6-Flash`；固定 JSON 契约 `{"text":"..."}`；已知延迟 4–6 秒、无词级时间戳、依赖提示词 |

顺序与降级：已配置的 `HttpAsrEngine` → 系统识别 → 实验引擎。`HttpAsrEngine` 运行时失败（402/429/超时/格式）且实验开关开启时，用**同一段录音**交给实验引擎重试，并在界面提示已降级。

录音格式统一为 16 kHz 单声道 WAV（Web 端由 `record_web` 编码），避免各识别服务对 webm/opus 兼容性不一致。

### 2.5 音频格式与采样

| 环节 | 格式 | 参数 | 理由 |
|---|---|---|---|
| 录音（送 ASR） | PCM16 WAV 或直接流 | 16 kHz、单声道、16 bit | Whisper 系模型的原生输入；系统识别也接受 16k |
| 端侧 ASR 输入 | 16 kHz PCM | 单声道 | 重采样成本低、模型要求 |
| 录音留档（可选） | 不保留 | — | 隐私优先；只在需要复听"我说的"时临时保留 |
| TTS 输出 | `audio-24khz-48kbitrate-mono-mp3` | 24 kHz、48 kbps、单声道 | Edge TTS 官方可选格式中体积/音质平衡点 |
| 系统 TTS | 由引擎决定 | — | 不落盘，直接播 |

**采样率不一致的处理**：录音 16 kHz、播放 24 kHz 是两条独立链路，不需要重采样；若后续做"跟读对比"，再引入统一 24 kHz。

### 2.6 后台行为

| 场景 | 设计 | 原因 |
|---|---|---|
| 对话中熄屏 | 用 `wakelock_plus` 保持常亮 | 按住说话需要屏幕可用 |
| 切到后台 | 立即暂停播放与录音，会话标记"中断"，回到前台可继续 | Android 后台录音在多数 ROM 上会被限制或静音 |
| 锁屏 | 同"切后台"；超过 5 分钟未回来，结束会话并保存草稿 | 避免半个会话永远挂着 |
| 来电/其他 App 抢占音频焦点 | 收到 `audio_session` 中断事件 → 暂停播放，显示"已暂停" | 避免突然外放 |
| 长时间合成 | 不做后台任务 | 单句合成通常 <2s，无需前台服务 |

**结论**：MVP **不承诺任何后台能力**，这也是"按住说话 + 回合制"的直接好处。

### 2.7 网络与流式

| 项 | 选择 | 说明 |
|---|---|---|
| HTTP 客户端 | `dio` 5.11.1 / MIT | 拦截器可统一注入鉴权、超时、错误归一；`CancelToken` 支持取消 |
| SSE 解析 | 自写轻量解析（按行切 `data:`） | 现成 Dart SSE 包维护状态参差（未核实），自己解析 60 行更可控 |
| WebSocket | `web_socket_channel` | Edge TTS 用；成熟、维护活跃 |
| 连通性 | `connectivity_plus` 7.3.2 / BSD-3 | 弱网/断网时给明确提示，而不是让用户等超时 |

**为什么不用现成 OpenAI Dart SDK**：Flutter 端没有官方 Dart SDK（**未核实**是否有可靠第三方实现）；且需求本身要求"只用最小公共协议"，自写更贴合 C1，也便于做参数降级。

## 3. 总体架构

### 3.1 运行形态

```text
┌─────────────────────────── Android / Flutter App ───────────────────────────┐
│                                                                             │
│  UI 层（页面 / 组件）                                                        │
│      │                                                                      │
│  状态层（Riverpod Notifier：会话状态机、配置、统计）                          │
│      │                                                                      │
│  领域层（Scenario / Turn / Correction / Phrase）                             │
│      │                                                                      │
│  ┌───────────────┬────────────────┬────────────────┬───────────────────┐    │
│  │ LlmClient     │ AsrEngine      │ TtsEngine      │ Repository        │    │
│  │ ↓             │ ↓              │ ↓              │ ↓                 │    │
│  │ OpenAI 兼容   │ 系统识别 /     │ Edge TTS /     │ Drift + 文件      │    │
│  │ 适配器(SSE)   │ Whisper        │ 系统 TTS       │ + SecureStorage   │    │
│  └───────────────┴────────────────┴────────────────┴───────────────────┘    │
└──────────┬────────────────────────────┬─────────────────────────────────────┘
           │ HTTPS                      │ WSS
           ▼                            ▼
   用户自填 base_url                Edge TTS 服务
   (OpenAI 兼容 /chat/completions)  (非官方，可降级)
```

**没有自建后端**：所有请求由 App 直连用户配置的接口与 Edge TTS。这样个人项目零运维，代价是密钥在端上、无法做服务端兜底。

### 3.2 模块边界

| 模块 | 职责 | 不负责 |
|---|---|---|
| `LlmClient` | 组装消息、发请求、解析流、错误归一、取消 | 提示词内容、场景逻辑 |
| `AsrEngine` | 音频 → 文本（+ 置信度/是否结束） | 断句策略、纠错 |
| `TtsEngine` | 文本 + 音色 + 语速 → 可播放音频/句柄 | 播放队列编排 |
| `TtsCache` | 缓存命中/写入/淘汰 | 合成本身 |
| `ConversationController` | 回合状态机、超时、取消、降级 | 具体网络细节 |
| `PromptBuilder` | 场景 + 水平 + 历史 → 消息数组 | 请求发送 |
| `ReviewService` | 会话结束 → 结构化复盘 | 展示 |

### 3.3 建议目录结构（仅约定，不创建）

```text
lib/
  app/          # 启动、主题、路由、全局错误处理
  core/         # Result、错误类型、日志（脱敏）、常量
  data/
    db/         # Drift 表与 DAO
    repositories/
    secure/     # Key 存取
  domain/       # 实体与用例：开始会话、提交回合、结束复盘
  features/
    home/ scenario/ conversation/ review/ history/ phrasebook/ settings/
  services/
    llm/        # client、openai_compatible、sse_parser、error_mapper
    asr/        # engine、system_asr、whisper_asr
    tts/        # engine、edge_tts、system_tts、cache
    audio/      # recorder、player、audio_session_manager
```

**分层原则**：`features` 只能依赖 `domain` 与 `services` 的接口；`services` 内部实现可以替换，不允许把 `dio` 类型泄漏到 UI。

## 4. 语音链路

### 4.1 回合状态机

```text
        ┌──────────────────────────────────────────────┐
        │                    Idle 空闲                  │
        └───┬──────────────────────────────────▲───────┘
  按下 PTT  │                                  │ 播放结束 / 出错并重试
            ▼                                  │
     ┌─────────────┐  松手 / 30s 上限   ┌──────┴──────┐
     │ Recording   │──────────────────▶│ Transcribing│
     │  录音中      │                   │   识别中     │
     └─────┬───────┘                   └──────┬──────┘
           │ 权限拒绝 / 无输入 / 超时           │ 成功
           ▼                                  ▼
     ┌─────────────┐                   ┌──────────────┐
     │ Error(可恢复)│◀──────────────────│ Thinking 等待 │
     └─────────────┘   请求失败/超时     │   模型回复    │
                                       └──────┬───────┘
                                       首句就绪  │
                                       ┌──────▼───────┐
                                       │ Speaking 播放 │
                                       └──────┬───────┘
                                              │
                                              ▼
                                            Idle
```

**状态与 UI 的对应**

| 状态 | 用户看到 | 可执行操作 |
|---|---|---|
| Idle | 大号"按住说话" | 按住、切换文字输入、看历史 |
| Recording | 波形 + 计时 + "松开发送" | 松手、上滑取消 |
| Transcribing | "识别中…" 骨架 | 取消（回到 Idle）、改文字 |
| Thinking | 用户气泡已出现 + AI "正在输入" | 取消（中止本回合）、看提示 |
| Speaking | AI 气泡 + 播放指示 + 逐句高亮（P1） | 停止、重听、暂停后按住说话 |
| Error | 明确原因 + 两个按钮 | 重试 / 改用文字 |

### 4.2 一次回合的时序

```text
用户            UI              Controller          ASR          LLM           TTS/Player
 │ 按下           │                  │                │            │                │
 ├───────────────▶│  stopPlayback()  │                │            │                │
 │                ├─────────────────▶│ 申请焦点/权限   │            │                │
 │                │                  ├───start()─────▶│            │                │
 │ 说话           │  波形/计时        │                │ 实时音量    │                │
 │ 松手           │                  │                │            │                │
 ├───────────────▶│  stop()          │                │            │                │
 │                ├─────────────────▶├───stop()──────▶│            │                │
 │                │                  │◀── transcript ─┤            │                │
 │                │  用户气泡         │                │            │                │
 │                │                  ├── chat(stream) ────────────▶│                │
 │                │                  │                │            │ 首 token        │
 │                │                  │◀────────────── delta ───────┤                │
 │                │  AI 气泡逐字       │  到句末标点 → 送首句 ──────────────────────▶│
 │                │                  │                │            │                │ 合成+播放
 │                │  听             ◀───────────────────────────────────────────────┤
 │                │                  │◀──────────── 剩余 delta ────┤                │
 │                │                  │  后续句进播放队列 ──────────────────────────▶│
```

**关键点**
- "首句就绪即合成"是延迟优化的核心：不等整段回复完成。
- 用户气泡在识别完成后立即出现，让用户知道"系统听到了什么"，这是纠错与信任的基础。
- 播放期间用户可以按 PTT：**先停播再录音**（见 4.7），这是"手动打断"，不是全双工 barge-in。

### 4.3 流式边界

| 边界 | 定义 | 处理 |
|---|---|---|
| 录音结束 | 松手或 30s 上限 | 停止采集，进入识别；不足 0.4s 视为误触，直接回 Idle |
| 识别结束 | 引擎回调 final 结果，或静音 1.2s | 取 final 文本；空结果 → 提示重说 |
| 首字超时 | 流式 6s 无任何 `delta` | 中止流式，转非流式请求（同参数） |
| 整段超时 | 非流式 30s / 流式 45s 未结束 | 中止并给"重试 / 改文字" |
| 句子切分 | 遇 `.` `?` `!` 且长度 ≥8 字符，或累计 ≥120 字符 | 切出的句子进入 TTS 队列 |
| TTS 首包 | 4s 未收到音频 | 该句改用系统 TTS 读出（不阻塞后续句） |
| 播放结束 | `just_audio` 完成事件 | 回 Idle，启动下一回合等待 |

**不做的事**：不做声学端点检测（VAD）自动断句。按住说话已经把"什么时候结束"交给用户，VAD 只会增加误判。

### 4.4 超时与重试

| 环节 | 超时 | 重试 | 退避 | 不做重试的情况 |
|---|---|---|---|---|
| 录音启动 | 1.5s | 1 次 | 立即 | 权限被拒 |
| 系统识别 | 8s（单次会话 45s 上限） | 1 次 | 300ms | 无可用识别服务 |
| LLM 首字（流式） | 6s | 1 次（转非流式） | — | 401/403/404 |
| LLM 整段 | 30s（非流式）/ 45s（流式） | 2 次 | 1s / 2s | 401/403/404/400 |
| TTS 首包 | 4s | 1 次 | 500ms | 连续 2 次失败 → 切系统 TTS |
| 翻译 | 10s | 1 次 | 1s | 主链路已结束则可放弃 |
| 复盘生成 | 30s | 1 次 | 2s | 失败时给"重试生成"，不阻塞保存会话 |

**重试必须可取消**：用户点"取消"或再次按住说话时，所有在途请求立即 `CancelToken.cancel()`，避免"旧回复盖新回复"。

### 4.5 失败降级矩阵

| 失败点 | 用户可见 | 降级动作 | 会话是否继续 |
|---|---|---|---|
| 麦克风权限被拒 | 引导去系统设置 | 自动切"文字输入" | 是 |
| 系统识别不可用（国产 ROM 常见） | "当前设备不支持语音识别" | 切端侧 Whisper（若已安装模型）；否则文字输入 | 是 |
| 识别结果为空 | "没听清，再说一次？" | 保留本次录音可重试 1 次 | 是 |
| LLM 401/403 | "接口校验失败，去设置检查 Key" | 不重试，跳设置入口 | 是（可改配置后重试本回合） |
| LLM 429 | "请求太频繁，稍等" | 3s 后自动重试 1 次 | 是 |
| LLM 5xx | "模型服务异常" | 退避重试 2 次；仍失败给"重试本回合" | 是 |
| LLM 返回空/超长/跑题 | 正常展示（超长截断） | 客户端截断 + 一次"请简短回答"重试（P1） | 是 |
| Edge TTS 失败 | 不提示或一次性轻提示 | 切系统 TTS 朗读同句 | 是 |
| 系统 TTS 也不可用 | 只显示文字 | 静音降级 + "重试朗读" | 是 |
| 网络断开 | 顶部提示条 | 本回合失败可重试；历史与表达本仍可读 | 是 |
| 复盘生成失败 | "本次没能生成总结" | 提供手动重试；会话记录已保存 | 会话已结束 |

**设计原则**：任何单点失败都**不允许**导致"会话必须重开"。这是 F2 验收标准的技术保障。

### 4.6 两条旁路：翻译与提示

**旁路定义**：不进入主对话历史、不影响 AI 下一句的生成。

#### 翻译旁路

```text
用户点按 AI 消息
   → 查 message.text_zh 是否已有
       → 有：直接展示（本地，0 延迟）
       → 无：异步请求（独立 prompt，temperature 低）
              → 成功：写回 message.text_zh + 展示
              → 失败：保留英文，给"重试"
```

- 翻译请求**不写回**对话上下文；不会让 AI 以为"用户说了中文"。
- "常开字幕"模式下，在 AI 消息完成后批量补翻，可并发 2–3 条，但要有上限（避免一次会话几十个请求）。
- 翻译结果持久化到 `message.text_zh`，重看历史不再请求。
- **与对话同一个模型**：翻译走 `_config()` 返回的 `LlmConfig`（同一 Base URL / 模型 / 密钥），没有独立翻译模型配置。差异只在 `stream=false`、`temperature=0.3`、`max_tokens=512` 与独立 prompt；对话是 `stream=true`、`max_tokens=700`。
- **为什么会出现「对话正常、翻译报错」**：思考型模型（如 `GLM-5.3-Flash`）先产出 reasoning 再产出正文，`max_tokens` 过小时非流式 `content` 为空，旧实现直接判为「模型没有返回正文内容」；旁路 15s 超时也会误伤。现改为 512 tokens / 25s，并按 `message.content`（字符串或 content 数组）→ `reasoning_content` → `delta.content` → `choices[0].text` 依次兜底。
- 非流式仍拿不到正文时，旁路自动降级到与主对话相同的 `streamChat` 路径重取一次；鉴权 / 404 / 限流等错误不降级。译文只取第一行含中文的正文（`PromptBuilder.cleanTranslation`），英文或思考内容不会当译文展示；失败保留英文原文并给「重试翻译」。

#### 提示旁路

| 级别 | 是否走模型 | 输入 | 约束 |
|---|---|---|---|
| L1 重听/慢速 | 否 | 上一条 AI 音频 | 本地变速播放；失败则重合成 |
| L2 关键词/句型 | 是 | 当前场景 + 上一条 AI 消息 | 只输出 3–5 个词/一个句型，禁止完整句 |
| L3 参考回答 | 是 | 同上 + 用户水平 | 只输出 1 句英文 |
| L4 中→英 | 是 | 用户输入的中文 + 场景 | 输出 1 句可直接说的英文 + 一行中文对照（可直接复用用户输入的中文） |

- 所有提示请求使用**独立 prompt 与独立消息数组**，结果只进 UI，不进主对话历史。
- L2–L4 的旁路 prompt 固定输出 `EN:` / `ZH:` 两行，一次请求同时拿到英文提示与中文对照，`HintParser` 对未按格式返回的内容做退化解析；L4 中文对照可直接复用用户输入的中文。只有模型完全没按两行格式输出时，才对英文提示补一次翻译旁路，失败也不影响英文提示。
- 结果需要标记 `is_hint = true`，复盘时据此统计"有辅助的回合"；提示气泡支持点按翻译与常开字幕。
- 提示结果不自动发送；用户必须自己按住说或点发送（与 F4 验收一致）。

### 4.7 录音/播放冲突与设备切换

#### 互斥规则

| 场景 | 行为 |
|---|---|
| 播放中按下 PTT | 立即 `stop()` 播放 → 释放焦点 → 开录音（用户主动打断，MVP 支持） |
| 录音中 AI 语音到达 | 不可能：录音期间不发起新请求；若上一回合仍在播，已在按下时停止 |
| 录音中收到系统通知音 | 保持录音；不做特殊处理（未核实各 ROM 表现） |
| 播放中切到后台 | 暂停播放；回前台不自动续播，显示"继续播放" |

#### 音频焦点与路由

1. 统一由 `audio_session` 管理：进入对话页时配置为"语音通信"类会话（`AudioSessionConfiguration.speech()`）。
2. **播放**：走媒体路由（扬声器/有线耳机/蓝牙 A2DP）。
3. **录音**：需要输入路由（手机麦克风/有线耳机麦/蓝牙 HFP）。蓝牙从 A2DP 切到 HFP 通常有几百毫秒延迟，**未核实**具体机型差异。
4. 因此录音启动时**不主动切换扬声器/听筒**，只申请麦克风；避免"为了录音把声音切到听筒"的突兀体验。
5. 监听到音频设备变化（耳机拔出/蓝牙断开）：
   - 播放中 → 暂停 + 提示"音频设备已断开"；
   - 录音中 → 停止录音，保留已录部分并进入识别。
6. 被来电或其他 App 抢占焦点 → 暂停播放，标记中断；**不自动恢复播放**。

#### 打断策略

- **支持**：用户按下 PTT 打断 AI 播放（手动）。
- **不支持**：语音触发打断（barge-in）、AI 边听边说。
- 理由：全双工需要回声消除与流式 ASR+TTS，延迟与成本都超过个人项目收益（需求 Q2 / B2）。

## 5. Edge TTS 接入

### 5.1 协议与端点

| 项 | 内容 |
|---|---|
| 协议 | WebSocket Secure（WSS） |
| 端点 | `wss://speech.platform.bing.com/consumer/speech/synthesize/readaloud/edge/v1` |
| 查询参数 | `TrustedClientToken`、`Sec-MS-GEC`、`Sec-MS-GEC-Version`、`ConnectionId` |
| 请求头 | `Origin: chrome-extension://jdiccldimpdaibmpdkjnbmckianbfold`、`User-Agent`（Edge 桌面版 UA） |
| 输出 | 二进制音频帧（默认 MP3）+ 文本控制帧（`Path:turn.start` / `audio.metadata` / `turn.end`） |

> 端点是社区长期使用的非官方地址，**不是公开 API**；微软未承诺兼容性。2026-11 是否仍可握手**未实测**，M1 必须先用最小脚本验证。

### 5.2 鉴权怎么来

没有 API Key。请求依赖两样东西：

1. **`TrustedClientToken`**：Edge 客户端里写死的公开常量（社区文档中广泛出现，如 `6A5AA1D4EAFF4E9FB37E23D68491D6F4`）。它会随 Edge 版本变化。
2. **`Sec-MS-GEC` 签名**：反滥用参数，算法为
   - 取当前 Unix 时间 + Windows epoch 偏移，换算成 100ns tick；
   - 向下取整到 5 分钟；
   - 与 `TrustedClientToken` 拼接后做 SHA-256，取**大写十六进制**。

`Sec-MS-GEC-Version` 为固定的 Edge 版本串（形如 `1-130.0.2849.68`）。

**含义**：这套机制是"模拟官方客户端"，不是授权接入。因此：
- 不能保证长期有效；
- 请求频率、地区、IP 可能被限流；
- 用户量一大就可能失效（个人自用风险可控）。

### 5.3 SSML 与消息格式

一次合成需要发两条文本帧：

1. **配置帧**（`Path:speech.config`）：声明输出格式与元数据选项，例如
   `audio-24khz-48kbitrate-mono-mp3`、开启 `wordBoundary`（用于 P1 逐词高亮）。
2. **SSML 帧**（`Path:ssml`）：`<speak>` 内包含 `<voice name="en-US-AriaNeural">`、`<prosody rate="+0%">` 与文本。

要点：
- 文本必须做 XML 转义（`&`、`<`、`>`），否则整段合成失败。
- 语速用 `rate` 百分比；0.8x ≈ `-20%`，1.2x ≈ `+20%`（映射关系需实测微调）。
- 单次文本建议 ≤300 字符；超长时按句切分多次合成，避免被截断。
- 音色名以 Edge 当前可用列表为准；文档不硬编码"最新"音色，用可配置清单 + 内置默认值。

### 5.4 流式播放

**MVP（M1–M2）**
```text
文本 → WSS 合成 → 收到全部二进制帧 → 拼成完整 MP3 → 写缓存文件 → just_audio 播放
```
- 优点：简单、seek 正常、失败可整体重试。
- 缺点：首字延迟 ≈ 合成总时长（短句通常 300–800ms，长句更久）。

**优化（M2 之后，可选）**
- 边收边写文件，`just_audio` 对一个持续增长的文件播放（Android 上可行但 seek 行为需实测）。
- 或按句切分：第 1 句合成完就开始播，第 2 句在后台合成 → 感知延迟显著下降。
- **优先做"按句切分"而不是"同句流式"**：实现难度低，收益接近。

### 5.5 断音、超时与重试

| 问题 | 现象 | 处理 |
|---|---|---|
| 连接超时 | 3s 未完成握手 | 关闭连接，重试 1 次，再失败切系统 TTS |
| 首音频帧超时 | 4s 无二进制帧 | 中断本次合成，切系统 TTS 读该句 |
| 合成中途断流 | 未收到 `turn.end` 就断开 | 丢弃半截音频（避免播出怪声），重试 1 次 |
| 403 / 握手拒绝 | 签名或 Token 失效 | 重算 `Sec-MS-GEC` 重试 1 次；仍失败 → 熔断 10 分钟并全局切系统 TTS |
| 长文本截断 | 音频明显不完整 | 按句切分重新合成剩余部分 |
| 频繁失败 | 连续 2 次失败 | 本次会话内直接使用系统 TTS，不再尝试 Edge（保护体验） |

**熔断策略**：连续失败 2 次 → 会话内降级；连续 3 次跨会话失败 → 全局默认切系统 TTS，并在设置页提示"Edge 语音暂不可用"。

### 5.6 缓存

| 项 | 设计 |
|---|---|
| 存储位置 | 应用私有目录 `tts/` |
| 缓存键 | `sha256(engineVersion + voice + rate + 归一化文本)` |
| 归一化 | 去首尾空白、合并连续空格、统一引号；不做大小写转换（影响发音） |
| 元数据 | 存数据库表 `tts_cache`（键、路径、字节数、创建时间、最后使用时间） |
| 命中条件 | 文件存在且大小 > 0 |
| 淘汰 | LRU：超过 300 个文件或 80 MB 时，删除最久未使用 |
| 失效 | 引擎版本/音色变更时，键自然变化，旧文件由 LRU 清理 |
| 清理入口 | 设置页"清理语音缓存" |

**高命中场景**：场景目标表达、常见开场白、重听同一句、复盘里的改进句。这些几乎零成本。

### 5.7 抽象层设计

```dart
// 仅表达接口形状，不是实现
abstract class TtsEngine {
  String get id;                       // 'edge' | 'system'
  Future<List<TtsVoice>> voices();     // 音色清单（系统引擎可能为空）
  Future<TtsResult> synthesize(
    String text, {
    required String voice,
    required double rate,
    bool allowCache = true,
  });
  Future<void> cancel();
}

class TtsResult {
  final String? filePath;   // 已落盘
  final Duration duration;  // 未知时为零
  final bool fromCache;
}
```

**上层只依赖 `TtsEngine`**：
- `TtsRouter` 负责"先 Edge、失败切系统、全局熔断"；
- 页面只调用 `speak(text)` / `stop()`，不关心是文件还是实时流；
- 换引擎 = 新增实现 + 改注入，页面零改动。

**音色处理**：不同引擎音色集合不同。设置里存"逻辑音色"（如 `female_us`），由适配器映射到具体 `voice` 名；映射不到时用该引擎默认音色，不报错。

### 5.8 替换与备选

| 备选 | 接入成本 | 适用场景 |
|---|---|---|
| 系统 TTS（`flutter_tts`） | 低 | 默认兜底，已内置 |
| Piper（端侧） | 高（模型打包、推理集成、GPL 许可） | 完全离线、长期可用性优先 |
| Kokoro（端侧/服务端） | 中高（部署方案未核实） | 音质要求高且能接受包体 |
| 其它在线 TTS（自建/第三方） | 中（需 Key 与计费） | 用户愿意付费换稳定 |

**结论**：抽象边界定在"文本 → 音频文件/句柄"，任何新引擎都不触碰对话逻辑。

## 6. 数据模型与本地存储

### 6.1 表结构

```text
scenario ──1:n── session ──1:n── message ──1:n── correction
                     │
                     └──1:n── phrase（也可独立存在，记录来源）

llm_profile（独立）
setting（独立，键值）
tts_cache（独立，按内容哈希）
app_meta（独立，schema 版本等）
```

### 6.2 字段定义

#### `scenario` 场景

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | 稳定 ID（如 `cafe_order`） |
| title_zh / title_en | TEXT | 显示名 |
| category | TEXT | 分类：日常 / 工作 / 旅行 / 社交 / 健康 / 观点（场景库 Chip 与图标用） |
| level | TEXT | A2 / B1 / B2 |
| ai_role | TEXT | AI 扮演的角色（英文描述，进 prompt） |
| user_goal | TEXT | 用户要达成的目标 |
| opening_line | TEXT | AI 开场白 |
| target_phrases | TEXT(JSON) | 5 条目标表达 |
| expected_turns | INTEGER | 预期回合 |
| success_criteria | TEXT | 成功条件（进 prompt） |
| branch_hint | TEXT | 1–2 个意外分支提示 |
| is_builtin | INTEGER | 1 内置 / 0 自定义（P1） |
| sort_order | INTEGER | 首页排序 |

> 场景内容用 JSON 字段而不是拆表：场景数量少、结构会变，拆表收益低。

> **2026-11-10 场景库扩容（需求 §0.1）**：内置场景由 2 个扩到 26 个（新增 24 个）。**表结构、`schemaVersion`、`LocalStore` 接口与 SQL 全部不变**：种子按 `id` 幂等 upsert，老设备覆盖安装后下次启动自动获得新场景，不需要迁移。`category` 由场景库 Chip 与分类图标映射消费；`target_phrases` 追加进 `chatSystem` 作为自然引导（不列出、不测验、不强制）；「练过次数」由 `session.scenario_id` 在 `scenarioLibraryProvider` 中派生聚合，不新增冗余字段。新增 `/scenarios` 全屏页（`ScenarioLibraryPage`），首页只保留 2 张推荐卡 +「全部 26 个」入口。详见 `docs/research-practice-scenarios-2026-11.md`。

#### `session` 会话

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | UUID |
| scenario_id | TEXT FK | 关联场景（可为空：自由聊 P2） |
| started_at / ended_at | INTEGER | 毫秒时间戳 |
| duration_sec | INTEGER | 有效时长（累计在对话页里的秒数，**不含退出后的墙钟差**；每 15 秒与退出时落盘） |

| review_json | TEXT? | 复盘结构化结果；重新进入对话页续练时清空，便于结束后重新生成 |
| cost_estimate | REAL? | 本地估算成本（可选） |

> **2026-11-10 会话续练（需求 §0.2）**：`ended_at` 只在 `completed` 时有值，半路退出必须清空；`status` 的 `aborted` 从未使用，正式改为 `in_progress`。**表结构与 `schemaVersion` 不变**。`SessionRepository` 增加 `pauseSession` / `resumeSession` / `recoverExitedSessions`，`finishSession` 的时长改由 `ConversationController.elapsedSec` 传入。旧版本把半路退出误标为 `completed` 且没写 `review_json` 的会话，在 `main()` 启动时一次性回收（`app_meta: resume.recovery.v1`）；未完成会话里明显大于「首条→末条消息跨度」的 `duration_sec` 也一次性重算（`app_meta: resume.durationfix.v1`）。两者都只跑一次、不动已有 `review_json` 的已完成复盘。边界：若用户曾显式点「结束并复盘」但复盘生成失败并退出，该会话同样没有 `review_json`，会被回收为可续练；此时用户重新点「结束并复盘」即可，不会丢消息。练过次数、月度成本等派生统计仍从 `session` 聚合，不新增冗余字段。

### 6.3 迁移与一致性

- Drift 的 `schemaVersion` + 迁移脚本，每次结构变更必须写迁移（个人项目也建议保留，否则换机/重装丢数据）。
- 写入会话采用**事务**：一次回合的 user/assistant 两条消息 + 更新 session 计数必须同一事务，避免"消息有、计数没"。
- 音频文件与数据库不是强一致：以数据库记录为准，启动时做一次孤儿文件清理（可选，M3）。

### 6.4 密钥保管

| 项 | 做法 |
|---|---|
| 存储 | `flutter_secure_storage`，键名 `llm_key_{profileId}` |
| Android 后端 | 默认 EncryptedSharedPreferences（依赖 Keystore） |
| 展示 | 只显示尾 4 位，不可复制回显 |
| 日志 | 统一脱敏：任何 header/body 日志过滤 `authorization`、`api_key`、`sk-` 前缀 |
| 备份 | `android:allowBackup=false`，或显式排除数据库与安全存储 |
| 删除 | 删除配置时同步删除安全存储条目 |
| 崩溃上报 | MVP 不做上报；若以后接入，必须过滤请求体 |

### 6.5 是否需要加密

| 数据 | 是否加密 | 判断依据 |
|---|---|---|
| API Key | **必须**（Keystore） | 泄露可直接产生费用 |
| 会话转写 | MVP 不加密 | 价值密度低、个人自用；有"删除"入口 |
| 表达本 | 不加密 | 同上 |
| 音频缓存 | 不加密 | 可重建，删了也无损 |
| 整库 | **不加密** | SQLCipher 方案 EOL（2026-11 查询）；整库加密会显著增加迁移与调试成本 |

> 如果以后有"把数据库导出给朋友"或"多设备同步"的需求，再评估整库加密或改为服务端存储。

### 6.6 数据生命周期

| 事件 | 处理 |
|---|---|
| 会话中断 | 存 `draft`，可在记录页继续或删除 |
| 会话完成 | 存 `completed` + `review_json` |
| 删除会话 | 级联删消息/纠错，并删除其音频文件 |
| 清空数据 | 删库 + 删 `tts/` 与 `recordings/` 目录 + 删安全存储 |
| 卸载 | 系统清理；不保留任何云端副本 |

### 7.4 从选场景到复盘的完整流程

```text
首页（本周进度 + 2 张场景卡）
  → 点场景卡
  → 场景详情（可试听目标表达；可跳过）
  → 开始对话：AI 开场白自动朗读
  → 回合循环：
       按住说话 → 松手 → 显示转写 → AI 流式回复 → 逐句朗读
       （卡住时：重听/关键词/参考回答/中→英；看不懂时：点按翻译）
  → 点结束 → 确认
  → 复盘（亮点 + ≤3 改法 + 2 表达 + 1 建议）
  → 存表达 / 再练一次 / 回首页
  → 首页统计 +1 次，显示"上次卡在哪"
```

**为什么这样排布**
- 首页只放 2 张卡：选择成本最低，符合"打开就能练"。
- 场景详情放在开始之前：给一点点准备（目标表达可试听），但允许跳过，避免"预习变门槛"。
- 对话页把"提示"和"说话"放在同一屏底部：卡住时手不用移动太远。
- 复盘独立成页而不是塞在对话末尾：避免"聊完还要继续读一屏"，也让复盘可回看。
- 记录与表达本放在底部导航而非首页：它们不是高频入口，但需要"随时可查"。

| 对话页 | 模型报错 | 按四类错误给不同文案（鉴权/模型/限流/服务） |
| 复盘页 | 生成失败 | "总结没生成成功，可以重试" |
| 记录页 | 无记录 | "还没有练习记录" |
| 表达本 | 无收藏 | 引导从复盘保存 |

### 7.6 视觉与交互约束

- 深色/浅色跟随系统；对话页字号可跟随系统缩放（口语练习需要看清转写）。
- 不用红色大面积标注错误（压迫感）；纠错标记用中性色 + 数字。
- 主按钮触达区 ≥56dp；按住说话按钮 ≥96dp 直径，便于盲按。
- 不做动画炫技；波形与三点加载即可。
- 参考的是"信息组织方式"，不是配色与图标：视觉上保持一个安静、低干扰的阅读环境。

## 8. 里程碑拆分

> 每个里程碑都能独立验收；不写时间估计，只定"做完的标志"。

### M0 骨架与文字闭环

**交付**
- Flutter 工程可编译、可装真机；主题、路由、依赖注入、错误处理骨架。
- 模型配置页 + 测试连接 + 安全存储。
- 用一张固定场景卡，进行**纯文字**对话（用户输入文字 → 模型回复文字），消息落库。

**做完的判断**
- 真机上填入真实 `base_url`/`key`/`model`，测试连接返回"可用"。
- 连续 5 轮文字对话正常，杀进程重启后消息还在。
- 401、超时、断网三种情况都有可读提示，App 不崩。

**风险验证点**：兼容实现是否支持流式；`/models` 是否可用。

### M1 真机跑通一次完整语音对话（关键里程碑）

**交付**
- 按住说话 → 系统识别 → 模型回复 → Edge TTS 播放 → 用户听到。
- 单场景（咖啡店点单）、单音色、无复盘、无提示、无翻译。
- 基础超时与"改用文字"兜底。

**做完的判断**
- 在 Android 真机上，不看文档、不重启 App，连续完成 **≥8 个回合**。
- "松手 → 听到 AI 首字"实测 p50 ≤3s（M1 只要求可用，不追求 1.5s）。
- 拔出耳机、锁屏、断网各试一次，App 不崩、会话不丢。
- 手动把 Edge TTS 域名改成不可用地址，App 能用系统 TTS 继续说完这句。

**风险验证点**：麦克风权限、音频焦点、国产 ROM 识别服务是否存在、Edge TTS 握手是否仍可用。

### M2 语音链路稳定与降级

**交付**
- 首句切分 + 播放队列；首字延迟优化。
- 完整超时/重试/取消；错误四分类文案。
- Edge TTS 熔断 + 系统 TTS 全局兜底；TTS 缓存（含 LRU）。
- 蓝牙/有线耳机切换处理；来电中断处理。
- 端侧 Whisper 接入（可选开关），用于无系统识别的机型。

**做完的判断**
- 首段语音延迟 p50 ≤1.5s、p95 ≤3s（本地 Wi-Fi，目标值）。
- 弱网（限速/丢包）下不出现"永远转圈"；最多 15s 内给出可操作提示。
- 连续 20 回合无音频状态错乱（如"以为在播其实没播"）。
- 断开 Edge TTS 后整场会话仍可完成（全程系统语音）。

### M3 复盘、表达本与记录

**交付**
- 会话结束 → 结构化复盘（1 亮点 + ≤3 改法 + 2 表达 + 1 建议）。
- 纠错标记与展开；改进句试听。
- 记录列表/详情；表达本；删除与清空数据。
- 首页周统计与"上次卡在哪"。

**做完的判断**
- 复盘在 30s 内生成；格式错误时给出"重试"而不是乱码。
- 用户能删除单条改法、删除整次会话、清空所有数据，且重启后确认生效。
- 重启后统计数字正确（本周次数、连续天数）。

### M4 第二场景 + 提示/翻译完整 + 打磨

**交付**
- 第二个场景（工作会议澄清）。
- L1–L4 提示完整；翻译三态 + "我想说"。
- 空态、异常态全部覆盖；无障碍与字号适配。
- 成本估算与月度上限提示。

**做完的判断**
- 需求文档 10.2 的 MVP 验收清单全部通过。
- 两个场景各完整跑 3 次，无阻塞性问题。
- 所有"失败路径"都能在 15s 内给用户一个明确下一步。

> 2026-11-10 补充：本节「两个场景各跑 3 次」是 M4 当时的验收口径，保持原样不改写；后续场景库扩容到 26 个属于 M4 之后的收尾项（里程碑 §12），不改变 M0–M4 的验收标准。

## 9. 风险与开放问题

### 9.1 技术风险

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| Edge TTS 端点/签名失效 | 中 | 朗读不可用 | 系统 TTS 兜底 + 熔断 + 缓存；长期可接 Piper |
| 国产 ROM 无系统语音识别 | 中高 | 语音输入不可用 | 端侧 Whisper 备选 + 文字兜底 |
| `edge_tts` Dart 包不成熟 | 中高 | M1 受阻 | 自写约 300 行 WSS 客户端；或先全程系统 TTS 验证其余链路 |
| 兼容接口不流式/参数报错 | 高 | 延迟高或请求失败 | 非流式回退、去参重试、错误四分类 |
| 录音插件机型兼容 | 中 | 录不到/杂音 | `record` 活跃度高；真机矩阵至少测 2 台；保留录音文件排查 |
| 音频焦点竞争 | 中 | 播放被打断/录音失败 | 统一 `audio_session`；进页配置、离开释放 |
| Flutter 升级破坏插件 | 中 | 编译失败 | 锁版本；升级单独开分支验证 |
| 延迟不达标 | 中 | 体验差 | 首句切分、缓存、短回复、提示词限制长度 |
| 长会话上下文超限 | 中 | 请求 400 | 只保留最近 N 轮 + 场景摘要；超限自动裁剪 |
| 模型不遵守"只问一个问题" | 高 | 体验跑偏 | 提示词硬约束 + 客户端截断 + 重试一次 |
| 许可证问题 | 低中 | 无法公开仓库 | 建立依赖许可证清单；GPL/AGPL/NC 默认不引入 |

### 9.2 成本

不预设具体金额（取决于用户选择的模型单价）。给出可计算的公式：

```text
单次会话 token ≈ 回合数 × (系统提示 + 场景 + 最近 6 轮历史 + 用户输入 + AI 回复)
              ≈ 10 × (500 + 200 + 300 + 40 + 90) ≈ 11,300 tokens
复盘 ≈ 2,000–3,000 tokens
翻译（按 30% 消息）≈ 10 × 0.3 × 200 ≈ 600 tokens
合计 ≈ 14,000–15,000 tokens / 次（约数，随提示词长度浮动）
```

| 成本项 | 说明 |
|---|---|
| LLM | 唯一真实成本；每周 3 次 ≈ 45k tokens/周 |
| Edge TTS | 免费（无 SLA） |
| 系统 TTS / 系统识别 | 免费（设备能力） |
| 端侧 Whisper | 免费，代价是包体与电量 |
| 存储 | 可忽略；缓存上限 80 MB |

**控制手段**：限制 AI 回复长度、只带最近 6 轮历史、复盘用独立压缩摘要、翻译按需。设置页展示"本次估算成本"，并在超过月度上限时提示（P1）。

### 9.3 仍需用户拍板

| # | 问题 | 为什么影响技术方案 |
|---|---|---|
| 1 | iOS 要不要做 | 决定音频会话配置、权限文案、里程碑是否需要分支 |
| 2 | ASR 基线用系统还是 Whisper | 决定是否要打包 75–150MB 模型、是否要处理模型下载 |
| 3 | Edge TTS 用现成 Dart 包还是自写 WSS | 决定 M1 的工期与可控性 |
| 4 | 数据库是否需要加密 | 决定是否引入额外依赖与迁移成本 |
| 5 | Android 分发方式（APK / 内测） | 决定签名、升级策略、是否要崩溃上报 |
| 6 | 月度 API 预算 | 决定上下文长度、是否要更激进的裁剪 |
| 7 | 是否接受"朗读偶尔降级为系统语音" | 决定是否需要投入本地神经 TTS |
| 8 | 视觉风格偏好（安静阅读型 / 活泼） | 决定首页与对话页的信息密度 |
