# 同类产品调研与优化方向建议：英语口语练习 App v0.1

- 文档状态：**调研参考，不作为决策依据**；产品范围与验收口径一律以 `requirements-speaking-app-v0.2.md` 为准
- 日期：2026-11-12
- 起因：用户反馈「作为学习英语使用觉得有欠缺，但不知道往哪个方向优化或加功能」
- 调研对象：可栗口语（重点）、Loora、Speak / ELSA / TalkPal / Praktika、影子跟读类产品
- 一句话结论：**缺的不是功能数量，而是「这次练完 → 下次练什么 → 上次改过的错有没有真的改掉」这一段；可栗值得抄的是四步链路和几个反馈细节，Loora 值得抄的是「把一条纠正变成 90 秒开口练习」。**

> 本文只做调研与建议，不改代码、不改需求范围。若决定实施任一条，按 `AGENTS.md` §3 同步更新需求文档、里程碑清单、开发文档与 UI 设计规范。

## 1. 先诊断：瓶颈在哪里

### 1.1 已经做到的（不要重复建设）

| 能力 | 现状 |
|---|---|
| 场景体系 | 26 个内置场景（6 分类 / 搜索 / 练过次数）+ 自建场景增删改 |
| 对话链路 | 按住说话（三引擎 ASR + 文字兜底）、流式回复、分句朗读、三态翻译、「我想说」、L1–L4 提示、优化句子、原声回放、鼓励动效、续练 |
| 课后反馈 | 1 个亮点 + 最多 3 条改法（原句/改进句/中文原因）+ 2 个表达 + 下次建议，可试听、可删除、可存表达本 |
| 记录与资产 | 会话历史与只读转写、表达本（增删改 / 朗读 / 已掌握）、周次数 / 分钟 / 连续天数、成本与延迟统计 |
| 二期听写 | 本地文件 + 字幕导入、切句对齐、离线逐词判分、教材库、错句本、只练错句、链接导入 |

单看「练一次」的闭环，功能密度已经高于多数同类产品的免费档。**继续往这个闭环里加按钮，收益递减。**

### 1.2 四个断点

| # | 断点 | 用户能感觉到的症状 | 代码里的证据 |
|---|---|---|---|
| A | **练完不知道有没有变好** | 首页只有「本周 2/3 次、累计 40 分钟」，是活动量不是效果量；练两周说不清自己强在哪 | `app/providers.dart` 只聚合次数/时长/连续天数；`me_page.dart` 只有成本与延迟；`practice.level` 是用户手填的设置项，没有测评或追踪 |
| B | **改过的错不会再见第二次** | 复盘里存下的表达进了表达本就再没被叫醒；错句本要自己想起来点进去 | `phrase.mastered` 只是布尔标记，无到期时间/间隔；`material_repository` 的错句本按「最近一次未通过」静态筛选；全库无 `due_at` / 复习排程 |
| C | **反馈是「看」不是「练」** | 复盘是一份读完就关的报告，改法没有当场再说一遍 | `prompt_builder.reviewMessages` 输出纯文本（亮点 / 纠错 `原句||改进句||原因` / 表达 / 下次），`review_page.dart` 只做展示、试听、删除、收藏 |
| D | **每次都要重新决定「今天练什么」** | 26 个场景 + 自建场景 + 教材库，入口越来越多，打开 App 先做选择题 | 首页只有 2 张推荐卡 +「继续上次」+ 统计；「下次建议」是复盘里一句中文文本，没有可执行入口 |

这四条正好对应可栗官网自己列的第三大痛点「**效果模糊：进步难量化，越学越容易迷失**」，以及需求文档 §1.1 的「练完没反馈 / 难以长期坚持」。换句话说：**闭环做完了「这一次」，还没闭环「这一个月」。**

### 1.3 一个方向判断

需求 §3.2 把主指标定为「连续 4 周、每周 ≥3 次、每次 ≥8 分钟」。能撬动这个指标的，不是更多场景或更炫的反馈，而是：

1. 让上次的收获**必须回来一次**（断点 B/C）；
2. 让打开 App **不用做选择**（断点 D）；
3. 让"进步"**看得见且可解释**，但不引入分数（断点 A）。

## 2. 调研材料与可信度分级

这一轮中文搜索结果里，绝大多数「2026 实测 / 排行榜 / 深度测评」是**同一批投放通稿**（句式、卖点、数字高度雷同），必须分级使用，否则会把营销口径当成产品事实。

| 级别 | 来源 | 用它回答什么 |
|---|---|---|
| 高（一手） | [可栗口语官网](http://www.oral-craft.com/)：四步链路、核心能力清单、三大痛点、场景预览 UI、FAQ | 「产品自己认为的价值主张与流程是什么」 |
| 高（一手） | [Loora 官网 Key Takeaways](https://www.loora.com/news/product-updates/key-takeaways)、[反馈系统支持页](https://www.loora.com/support/features/feedback-and-corrections) | 「反馈交互具体长什么样、设计动机是什么」 |
| 中（第三方聚合） | [apppricer 可栗评价摘要](https://apppricer.com/app/6449095944)、[Unstar 对 5 款 App 的 1–3 星评论分析](https://unstar.app/blog/is-speak-elsa-talkpal-loora-learna-ai-english-apps-legit-2026) | 「真实用户的抱怨集中在哪里」 |
| 低（宣传通稿，仅作功能线索） | 凤凰网 / 中华网 / 中国教育在线 / 今日头条 / 地方新闻网等一大批「测评」 | 「可能有哪些功能设计值得追查」，**不作为事实依据** |

**数字互相矛盾的典型例子**：官网写「1000W+ 学习者、4.9★」，通稿写「3500 万+ 用户」「80000+ 真实场景」「音素级纠音准确率 99.9%+」「对话延迟 100ms 以内」「全球唯一 / 全球首创」。这些数字不可核验、彼此冲突，**本报告的借鉴项不依赖任何一项数字**，只取其功能形态。

## 3. 可栗口语：值得抄的是链路，不是功能清单

### 3.1 官网确认的四步链路

> 选场景（内容针对岗位与语境）→ 打基础（场景核心句与词，先吃透）→ 实战对话（**目标导向通关 + 评分报告**）→ 进步追踪（专属能力画像，动态可见）

另有三条官网口径值得注意：

- **痛点定义**：场景失语 / 练法错位（跟读多、对话少）/ 效果模糊（没有清晰能力画像和变化轨迹，坚持靠感觉）。
- **场景按「行业与岗位」组织**，不是按「日常/旅行」这种泛分类；主张「每一句都指向下次用得上」。
- **FAQ 专门回应「会不会刷分却还是不会真说」**：回答是「以任务型对话和真实情景为主，**只有完成沟通目标才通关**」。这句话比任何评分功能都关键——**通关条件绑定沟通目标，而不是绑定分数**。

### 3.2 逐条对照

| 链路环节 | 可栗 | Saylo 现状 | 差距性质 |
|---|---|---|---|
| 1 选场景 | 按岗位/语境组织 | 26 场景按 6 分类 + 自建场景 | 基本对齐，无需再加场景 |
| 2 **打基础** | 核心句与词「先吃透」，进对话前先过一遍 | 场景卡展示 5 条目标表达、可试听、**可跳过** | **缺一个 60 秒预热环节**（但不该做成强制课程） |
| 3 **实战对话** | 目标导向**通关** + 评分报告 | `successCriteria` 只在场景详情页展示（`lib/features/scenario/scenario_page.dart`）并进 prompt（`lib/services/llm/prompt_builder.dart`），**用户看不到自己达没达成** | **缺可见的目标清单与达成判定** |
| 4 **进步追踪** | 能力画像 / 变化轨迹 | 只有次数、分钟、连续天数、成本、延迟 | **缺效果量指标**（但不必做成 CEFR 打分） |

### 3.3 五个值得单独拎出来的细节

| # | 细节 | 来源 | 为什么值得抄 |
|---|---|---|---|
| D1 | **场景预览卡**：一句「对方开场」+ 编号「对话目标」3 条（回应寒暄 / 抛一个话题 / 自然收尾）+「核心例句」2 条 +「关键词汇」3 个 | 官网场景预览弹层（一手） | 把抽象的 `successCriteria` 变成**可勾选的 3 件小事**；开场前就知道"这趟要办成什么"，显著降低开口焦虑 |
| D2 | **中式成因 + 双版本替换**：先讲中文直译陷阱和母语者思路差异，再给「口语日常版 / 正式商务版」两套说法并说明适用场合 | 多家通稿一致描述（未独立验证，中低可信） | 现有的 `reasonZh ≤25 字` 只能说"不地道"，说不清**为什么会这么错**；语体差异恰恰是 A2–B1 用户最缺的一层 |
| D3 | **长期错误记忆 + 跨对话复现**：记住反复踩坑的句型/音素/表达，后续对话主动拉出来再练，薄弱项进复盘本按遗忘曲线巩固 | 多家通稿一致描述（未独立验证） | 直接命中本文档断点 B；且这是**机制**不是内容，个人自用产品完全做得起 |
| D4 | **一句话生成情景课**：描述「下周主持项目会议」→ 约 30 秒生成含单词/例句/对话的一课 | 多家通稿一致描述（未独立验证） | 现有自建场景要手填 **10 个字段**（`lib/features/scenario/scenario_editor_page.dart`），填表本身就是劝退点；生成后允许微调即可 |
| D5 | **粒度可选**：3 分钟 mini 课 / 5–10 分钟一轮；先听 → 跟读 → 复述 → 对话 | 多家通稿一致描述（未独立验证） | 现在只有「10 分钟场景对话」和「听写」两种粒度；低能量日没有轻量入口，直接影响 4 周坚持率 |

### 3.4 反向提醒：可栗自己的差评

第三方评价聚合（apppricer，基于约 5800 条评分）里，用户**喜欢**：定制学习计划、界面顺手、实时发音反馈、价格；用户**抱怨**：

> Slow response time / **Poor progress tracking and messy course lists** / Inaccurate speech recognition and error handling / Aggressive marketing

中文独立测评也提到「AI 对话偶尔接不住话、部分入口藏得深、免费额度偏紧、嘈杂环境识别掉准确率」。

两点启示：

1. **「能力画像」宣传得很响，用户仍抱怨进度追踪差** → 说明画像好不好用取决于指标是否可解释、是否与下次练习相连，而不是图表多漂亮。
2. **场景越多，列表越乱** → 26 个场景已经够了，下一步该做的是「替用户挑一个」，而不是继续扩容。

## 4. 其他产品与品类共性

### 4.1 Loora：把「一条纠正」变成 90 秒练习（本轮最有价值的一条）

[官方产品更新](https://www.loora.com/news/product-updates/key-takeaways) 原文动机：

> "We built Key Takeaways to fix the most common problem with feedback: **you get too much of it, and remember none of it.**"
> "**One correction you drill is worth more than ten you scroll past.**"

具体设计：

- 每次对话结束**只挑一条**最大收益的改进（词汇 / 语法 / 发音三选一，依据「当前水平 + 已练过什么」）；
- 配一组 **practice cards**：把这条纠正**开口说出来**，做对得一颗星，全程约 90 秒；
- 可存入 Practice Tab，历史随时回看；
- 对话中也给纠错，但**分时机**：下划线 = 语法、高亮 = 发音，点词开卡、点「钢笔」看该句全部纠错；口头反馈量可在设置里调，书面反馈始终可点开；课后 Review 回看全部纠错。

**对 Saylo 的意义**：需求 §4.3 写「课后只留 1 个重点」，方向完全一致，但目前实现成了「1 个亮点 + 3 条改法 + 2 个表达 + 1 个建议」的**文本报告**。缺的是 Loora 那个动词——**drill**。补上这一步，不需要新表、不需要新模型能力（ASR 与二期词级判分现成），就能同时缓解断点 B 和 C。

### 4.2 品类共性差评：这些是「别做错」的边界

[Unstar 对 Speak / ELSA / TalkPal / Loora / Learna 的 1–3 星评论聚类](https://unstar.app/blog/is-speak-elsa-talkpal-loora-learna-ai-english-apps-legit-2026)（按差评占比）：

| 差评类型 | 占比 | 代表性原话 | 对 Saylo 的提醒 |
|---|---|---|---|
| 订阅自动续费 / 退订难 | 26% | — | 需求「不做支付/订阅」是正确取舍，坚持 |
| **AI 对话循环、浅** | 22% | "The AI asks the same three questions over and over. It is not a conversation, it is a script with a voice" / "It does not actually listen... replies with a generic line that ignores what I said" / "Stuck at small talk forever" | 主对话窗口是尾部 16 条消息、无跨会话记忆；**重复提问和话题不深入迟早会碰到** |
| 深度内容锁付费墙 | 18% | — | 个人自用天然没有这个问题 |
| **真实场景进步慢** | 16% | "Used it daily for three months and still froze up in an actual conversation with a person. The app does not prepare you for real speed" / "My pronunciation scores went up in the app but natives still could not understand me" | 「App 内指标 ≠ 真实能力」；能力轨迹必须选**可迁移的信号**，别造分数 |
| **识别误判伤信任** | 12% | "It marks my pronunciation wrong when natives understand me perfectly" / "Same word, different score each time. I stopped trusting the corrections" | 印证需求「不做发音分数 / 音素级评分」的判断；F10「只标可能听不清」是安全上限 |

另有观点指出连胜、彩纸、AI 夸奖、进度条构成「多巴胺循环」，奖励的是"感觉良好"而非真实输出。项目里已有 `RewardBurst` 正向动效，**够了，不宜再加勋章/排行榜**。

### 4.3 影子跟读类产品对二期听写的启发

Shadowing 类（ShadowingEnglish / Shadow Flow / Sayva / Echo Loop）的共同形态是：**真实素材按句切 → 逐句循环变速 → 开口跟读 → 逐词/逐音对比 → 收藏值得练的句子**。Echo Loop 把流程写成「盲听 → 精听 → 影子跟读 → 复述 → 复习」。

Saylo 二期已经做到「切句 + 逐句播放 + 0.75x + 听写判分 + 错句本」，**离"跟读/复述"只差一层输入方式**：把键盘输入换成「说一遍 + 用同一套词级 diff 判是否说全」。这比另起一条新功能线便宜得多，而且正好接上 §4.1 的 90 秒练习。

### 4.4 学习科学口径：不要改「温和模式」

检索到的纠错时机系统综述（[PMC 系统综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC9995700/) 等）结论是**即时 vs 延时反馈无统一定论**，多项研究显示无显著差异，效果取决于任务类型与错误是否阻碍理解。这与需求 §13 决策 5「纠错默认不打断，课后集中反馈」以及需求 §16.3 的记录一致。

**结论：不需要因为竞品「边聊边纠错」就把严格模式提前开放。** 该补的是课后那条纠正有没有被练过，而不是把纠正挪进对话里。

## 5. 借鉴清单（按价值 / 成本分级）

> 「现状」列均为已核对的代码事实；「与需求关系」列标注是否需要用户拍板。所有条目都**不动 §10.2 的 11 条 MVP 验收清单**。

### 第一档：直击四个断点，复用现有数据，改动小

| # | 项目 | 建议做法 | 验收口径 | 与需求关系 |
|---|---|---|---|---|
| **1** | **复盘尾部加「今日一条」90 秒开口练习**（Loora Key Takeaways） | 从本次改法/表达里挑 1 条 → 卡上给原句与改进句 → 按麦说一遍 → 复用 `dictation_scorer` 的词级 diff 判「说对没」→ 标记「已过 / 再来」→ 结果写回复习队列。不新增网络请求 | 复盘页内 90 秒可完成一次开口复述；判分离线；不改动原有复盘报告 | 与 §4.3「课后只留 1 个重点」一致，是补「练」不是加「看」 |
| **2** | **表达本 / 错句本升级为到期复练队列**（可栗 D3） | 新增 `review_item`（来源、due_at、间隔档位 1/3/7/14 天、最近结果、连续答对次数），简版固定阶梯即可，不上完整 SM-2；`phrase.mastered` 与错句本都接到同一队列 | 隔天打开有待复练项；完成后到期日顺延、连续错则缩短间隔；清空数据不误伤其它表 | 需求 §11 v0.2 已列「表达本随机复习」，§13 决策 13 把 SRS 留到后续 —— **现在解禁需你拍板** |
| **3** | **首页「今天练这个」**（可栗主动推荐 + 其"列表乱"差评反推） | 规则生成，不调模型：待复练项 > 上次未通过错句 > 上次提示次数偏多的场景再练一次 > 未练过的场景；卡上一句人话理由 + 一键开始 | 卡能一键进入练习；理由与数据对得上；无数据时给"随便来一段"而非空态 | 与 §3.1 目标 1「让开始练足够轻」一致 |
| **4** | **改法补「中式成因 + 双版本替换」**（可栗 D2） | `reviewMessages` 输出增加可选字段 `cause_zh` / `casual` / `formal` + 适用场合；`ReviewParser` 宽容解析，字段缺失就退回现有三列展示 | 同一句在「咖啡店点单」与「会议澄清」下语体明显不同；解析失败不崩、原报告仍完整 | 纯提示词与展示层，不改数据模型 |
| **5** | **场景目标清单 + 通关判定**（可栗 D1 + FAQ） | 把 `successCriteria` 拆成 3 条可见小目标（对话页可折叠）；结束复盘时让模型判定「已达成 / 待练」，写进 session；未达成项可一键「只练这条」 | 复盘显示 3 条勾选结果；判定失败不影响复盘生成；不做分数、不做排行榜 | 与「不做发音分数」不冲突；是把既有字段**用起来** |

### 第二档：体验提升明显，改动中等

| # | 项目 | 建议做法 | 验收口径 | 与需求关系 |
|---|---|---|---|---|
| **6** | **一句话生成自定义场景**（可栗 D4） | 编辑器顶部加「描述你想练的场合」→ 复用现有 `_sideChat` 生成结构化场景卡 → 用户确认/微调后保存；原 10 字段表单保留为手动编辑 | 生成失败可一键回退手填，不落半成品场景；不新增模型配置、不改场景表 | §0.3 已提前启用 F9，本条是降门槛，不改范围 |
| **7** | **课前 60 秒打基础**（可栗链路第 2 步） | 场景详情加可选「先热个身」：3 句核心表达 → 听 → 跟读 → 进对话；`clip_player` / TTS 复用，跟读只做「关键词是否说出」的弱判定，**不打分**；默认关闭、随时可跳过 | 全程 ≤60 秒；跳过不影响开练；无 TTS 时降级为纯文字 | 与 F1「场景卡可跳过」兼容，不能变成强制预习 |
| **8** | **3 分钟轻量模式**（可栗 D5 + Loora "little and often"） | 首页「3 分钟」入口 = 1 条待复练 + 3 回合微对话 + 1 条重点；复用同一会话表，用 `targetMinutes` 区分粒度 | 3 分钟内能完成并计入周次数；与 10 分钟模式数据口径一致 | 直接服务 §3.2 主指标；需确认是否放宽「每次 ≥8 分钟」的成功标准 |
| **9** | **防脚本化 / 话题深一层** | 给 `chatSystem` 注入极小「学习者档案」：最近常犯的 1–2 类错误、已掌握表达 3 条、上次话题；要求不重复同类提问、主动深挖一层；加「换个角度追问 / 提高难度」一键按钮 | 连续 3 次同场景不出现重复开场与同类提问；AI 仍只问 1 个问题 | ⚠️ **与 §0.3 第 7 条冲突**：该条明确「语境严格限于本次会话 + 场景卡，不含用户水平、纠错/复盘、表达本、其它会话」。**必须先由你拍板是否放开** |

### 第三档：让进步可解释，但要克制

| # | 项目 | 建议做法 | 验收口径 | 与需求关系 |
|---|---|---|---|---|
| **10** | **轻量能力轨迹（不做 CEFR 打分）** | 在「我的」加 4 条**可解释趋势 + 近 4 周折线**，全部由已有数据算出：① 平均每回合词数 ② 提示使用率 ③ 翻译查看率 ④ **改法复现率**（上次的改法在后面对话里有没有再用对）。每条配一句人话解释 | 每项能点开看「怎么算的」；无分数、无等级、无排名；断网可用 | ②③ 正是需求 §3.2 已有的次指标（提示 ≤3 次、翻译 ≤30%）；④ 由 #1/#2 产生。**完全绕开「不做分数」的非目标** |

**为什么不用可栗的 CEFR 画像 / 四维雷达**：单用户、无对照样本，5 分钟测评的信效度存疑；且 §3.3 明确不做分数。第 10 条用「你自己上一次 vs 这一次」替代「你 vs 标准」，既回答了「有没有进步」，又不会诱导刷分。可栗用户抱怨"进度追踪差"也说明：图表不是重点，**指标能不能指向下一步动作**才是。

## 6. 明确不建议借鉴

| 竞品功能 | 不做的理由 |
|---|---|
| 音素级评分、口型/舌位、跟读出分 | 需求 §3.3 非目标；Unstar 12% 差评正是「识别误判 / 同一个词每次分不同 → 不再信任纠错」；可栗真实评价也提识别不准。F10「只标可能听不清」是安全上限 |
| 80000+ 场景 / 场景市场 / 行业题库 / 雅思模考 | 与「不做课程/考试」冲突；可栗自身差评含「课程列表混乱」；26 个场景 + 自建 + 教材库已足够，再加只增选择成本 |
| 连胜打卡、学习排行榜、勋章、虚拟人外教 | 需求明确不做；多巴胺循环奖励"感觉良好"而非真实输出；虚拟人被用户吐槽分散注意力（需求 §16.3）。已有 `RewardBurst` 足够 |
| 流式全双工打断（barge-in）、边聊边纠错 | 需求 B2 与 §3.3 非目标；纠错时机研究无统一定论，不需要为此改温和模式 |
| 主动 CEFR 测评、能力雷达 / 薄弱项热力图 | 与「不做分数」冲突，且个人自用的测评缺乏校准意义；用第 10 条的可解释趋势替代 |
| 多端同步、账号、订阅 / 会员体系 | 需求明确非目标；订阅恰是品类第一大差评源（26%） |
| AI Agent 主动推送训练计划 / 每日提醒 | 单用户、无服务端，做成端内规则（第 3 条）即可，不必引入 Agent 概念 |

## 7. 建议路线

按「先补记住 → 再补好用 → 最后补看得见」推进，每批独立可验收，不做大改版。

| 批次 | 包含 | 做完会有的变化 | 怎么判断有效 |
|---|---|---|---|
| **批次 1：把「练过」变成「记住」** | #1 #2 #3 | 复盘从报告变成一次开口练习；旧错隔天会自己回来；打开 App 不用选 | 连续 4 周每周 ≥3 次（需求 §3.2 主指标）；待复练完成率可观测 |
| **批次 2：让反馈更贴自己** | #4 #5 #6 #7 | 纠错讲清中式成因与语体、场景目标可见、自建场景不填表、开场不卡 | 提示使用率下降、每回合有效词数上升、自建场景创建数 > 0 |
| **批次 3：让进步可解释** | #8 #10（#9 待拍板） | 低能量日有 3 分钟入口、能看到 4 条自己的趋势 | 4 周后能明确回答「哪方面变好了、凭什么」 |

**如果只做一件事**：做 **#1 + #2 的最小组合**——「复盘挑一条 → 当场说一遍 → 进到期队列 → 首页提醒回来再说」。它一次缓解断点 B / C / D 三个，完全复用现有 `correction` / `phrase` / `dictation_attempt` 数据与 `AsrEngine` / `dictation_scorer`，不碰对话状态机、不碰底部 4 Tab、不引入新依赖、不违背任何一条非目标。这也是与「再加 10 个功能」相比，最可能真正改变「觉得有欠缺」这一步的动作。
